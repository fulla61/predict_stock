## 2. ★ハイブリッド運用設計（Web / Excel / WeChat要約）— 最重要

Governance §11 の4原則を、現場動作レベルまで具体化する。設計原理は一つ:
**「工場に道具を変えさせない。変換コストはすべて当社側（システム+CN_OFFICE）が払う」**。

### 2.1 (a) チャネル・マトリクス（どの業務をどのチャネルで行うか）

| 業務群 | Web(Portal) | Excel | WeChat要約 |
|---|---|---|---|
| 寻厂・初筛・资质调查 | 商社側の一覧・比較ビュー（正） | 资质调查表の往復（正） | 工場との初回接触・催促 |
| 询价〜报价收集 | 比較テーブル自動生成（閲覧） | **询价单/报价回复の往復（正）** | 送付通知・未回答催促・質疑 |
| 打样〜黄金样 | サンプル評価記録・写真台帳（正） | 打样要求书・样品检查表（正） | 進捗確認・写真速報 |
| 规格书・品质标准・包装 | 承認済みSoTの閲覧 | **13シートExcel下発（正）**・工場签回 | 変更点の要約通知 |
| 生产前确认〜大货生产 | 進捗ダッシュボード（商社正） | PP会议记录・首件报告（正） | **日次/週次進捗（正）**・異常速報 |
| IPQC〜出货检验 | 検品結果の構造化ビュー（商社正） | **各種检验报告（正）** | 不良速報・判定通知 |
| ECR・不良整改・CAPA | Status管理・Gate連動（正） | ECR表・CAPA报告（正） | 受付通知・期限催促 |
| 出货资料・装柜・出货批准 | 出货批准のApproval（正・Portalのみ） | 装箱单/发票等（正） | 装柜写真・完了報告 |

原則:
1. **確定情報（仕様・価格・納期・判定）はExcel + システム登録が正**。WeChatは通知・催促・速報専用。
2. **出货批准（CN-LOGI-030）だけはPortal上のApproval操作のみ有効**（Hard Gate証跡のため。Excel・WeChatでの「同意」は無効）。
3. 工場のPortalログインは**必須にしない**。工場がPortalを使う場合も、同一データのExcelを常に取得可能とする（Governance §11-1）。

### 2.2 (b) Excel往復ライフサイクル

```
[1]生成 → [2]送信 → [3]工場記入 → [4]返信 → [5]構造化取込 → [6]差分レビュー → [7]SoT昇格 → [8]証跡保存
```

| # | 段階 | 実施者 | 内容 |
|---|---|---|---|
| 1 | 生成（EXPORT） | SYSTEM | SoT（承認済みDB）から中国語Excelを生成。ファイル名 `{ProjectID}_{DocType}_V{n}_{YYYYMMDD}_{DRAFT/APPROVED}.xlsx`。ProjectID/Version/透かしを埋込（§2.4） |
| 2 | 送信 | CN_OFFICE | WeChat/メールで送付。送信記録（宛先・日時・ファイルハッシュ）をDocumentに自動登録 |
| 3 | 工場記入 | FACTORY | 記入セルは黄色地・入力規則付き。それ以外はシート保護。記入欄はドロップダウン・数値・日付型を優先し自由記述を最小化 |
| 4 | 返信 | FACTORY→CN_OFFICE | WeChat/メールで返送。CN_OFFICEが受領登録（受領日時記録） |
| 5 | 構造化取込（PARSE） | SYSTEM+AI | 隠しメタシートのProjectID/Versionを照合（§2.4）→記入セルを抽出しDBへ仮登録（Status=PROVISIONAL相当のドラフト） |
| 6 | 差分レビュー | CN_OFFICE | AI提示の「前版との差分・規格書との矛盾・空欄」を確認。矛盾はWeChatDigestで工場へ質問 |
| 7 | SoT昇格 | CN_OFFICE/商社（Approval） | 承認操作でSoTへ昇格（Governance §6-3）。以後この内容が正であり、Excelは参照物になる |
| 8 | 証跡保存 | SYSTEM | 返信Excel原本（工場が触ったままのファイル）をDocumentとしてProjectに添付保存。**原本の上書き禁止** |

- 破損・様式崩れ・別ファイルでの返信（工場が自社様式で返すケースは頻発する）は [5] で自動取込を諦め、CN_OFFICEが手動転記して [6] へ進む（D_MANUAL_EXCEPTIONではなく通常フローの手動分岐として扱う）。原本添付は同じく必須。

### 2.3 (c) WeChatDigest（微信摘要）送受信フォーマット

**送信（システム→CN_OFFICE→工場）**: 1案件1メッセージ、固定4部構成。長文禁止（スマホ1画面≒15行以内）。

```
【CI-2026-0001 · 350ml不锈钢真空杯 · 摘要 08-10】
■ 待回复（2项）
  1. 询价单 CI-2026-0001-RFQ-01：请在 8/15（周五）前回复报价Excel
  2. 内胆钢材材质报告（SUS304）：尚未收到
■ 本期限（1项）
  · 打样交期确认：8/12 前答复
■ 变更点（1项）
  · 规格书升级至 V2（杯口尺寸公差修改：Φ85±0.5 → ±0.3）。
    请以 V2 文件为准，V1 作废。
■ 回复方式：报价请填Excel回传；简单确认可直接微信回复"确认+编号"。
```

**受信（工場WeChat→構造化取込）**: CN_OFFICE（またはAI）が受信メッセージを以下の型に要約してシステム登録する。登録時点でSoT候補、元メッセージのスクリーンショット/テキストはDocumentとして添付保存（Governance §11-2）。

```
【收到 · CI-2026-0001 · FA-0007 · 08-11 14:32】
类型: 报价补充回复（对应 RFQ-01 第3项）
内容摘要: 模具费=0（公模）；喷粉颜色定制需另收色粉调色费 RMB 300/色
影响项: Quote.tooling_cost=0 / Quote.color_fee=300
待办: 无
原文: [截图存档 DOC-…]
```

- 頻度規律: 定期Digestは**週1回**+イベント駆動（期限超過・変更発生・不良検知）のみ。日次送信は既読無視を招くため禁止（→【現実性メモ M2】）。
- 情報遮断: WeChatDigest生成時も Governance §8 を適用。顧客販売価格・粗利・他工場の価格/名称は**要約に含めてはならない**（生成テンプレート側で該当フィールドを参照不可にする）。

### 2.4 (d) チャネル間の版ズレ防止ルール

1. **埋込メタデータ**: 全出力Excelに (i)表紙セルの `项目编号 / 文件类型 / 版本 / 输出日期`、(ii)全シートヘッダの `{ProjectID} V{n}` 印字、(iii)隠しシート `_meta`（ProjectID / DocType / Version / 出力日時 / 生成元レコードID / SHA-256ハッシュ）の3点セット（Governance §7）。
2. **透かし**: `DRAFT`（草案/仅供参考）と `APPROVED`（已批准版本）の透かしを背景に敷く。DRAFT版で工場が生産準備を始める事故を防ぐため、表紙に赤字で「**草案，禁止依此生产 / ドラフト・これによる生産禁止**」を明記。
3. **返信版チェック**: 取込[5]で `_meta` のVersionを現行SoT版と照合。旧版への記入が返ってきた場合は自動でBLOCK扱いにせず、「旧版回答」フラグ付きで取込→差分レビュー[6]で新版との差異のみ再質問（工場に全部書き直させない。書き直し要求は回答率を下げる）。
4. **旧版の失効通知**: 新版発行時、WeChatDigestの「变更点」に必ず `V{n}文件作废、以V{n+1}为准`（旧版失効・新版が正）を記載。工場保管分の差替えまでは強制できないため、**首件确认（CN-PROD-020）で最新版参照を実物照合する**ことを版管理の最終防衛線とする。
5. **「最新版」というファイル名の禁止**（Governance §7-3）は工場返信ファイルにも適用: CN_OFFICEが受領時にリネームして登録する（工場へのリネーム強制はしない）。

## 3. 翻訳ルールブック（抜粋）

原則（5箇条）:
- **R1 定量化**: 曖昧な形容（きれい・しっかり・なるべく）は、検査距離・照明・数値限度・期限に必ず変換する。数値にできない場合は限度样（LimitSample）を正とする。
- **R2 期限付与**: 依頼文には必ず期限（具体日付+曜日）を付す。「お早めに」は翻訳禁止。
- **R3 直接表現**: 日本語の婉曲（検討します/難しいです）は中国語では誤読される。可否・条件・期限を直接書く。
- **R4 検査可能性**: 「〜がないこと」は「どの面を・どの条件で・何mm/何個まで許容か」の合否基準に変換する。
- **R5 用語固定**: Governance §1 のZH列のみ使用。同義語（例: 检查/检验、样板/样品）の揺れを禁止。出荷前現物検査は必ず「出货检验」。

変換例（最低10例）:

| # | 日本語原文（直訳禁止） | 現場中国語（変換後） | 適用原則 |
|---|---|---|---|
| 1 | 傷がないこと | A面在300mm距离、正常光照（600-800lux）下无可见划伤（长≥5mm或宽≥0.5mm的划伤不允许，以下允许2条以内） | R1 R4 |

```
        整改验证通过前，后续批次暂停出货。
   11.4 市场不良（日本端客诉）: 贸易公司提供样品/照片，工厂7个工作日内出
        分析结论；属工厂责任的，按合同承担退换/赔偿。
   11.5 责任判定依据: 本规格书 + 黄金样 + 检验记录 + 系统审批记录。

12. 生效
    本规格书经工厂盖章签回（或系统确认）后生效。
    工厂签字/盖章: ____________    日期: ____________
    贸易公司确认:   ____________    日期: ____________
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 5.3 の「防溅盖不承诺倒置不漏」は日本側の「漏れない」要求と衝突しやすい典型点。仕様書に**明記して商流上流（顧客説明・商品ページ表現）へフィードバックする**こと（A2/A6連携事項）。

## 7. Factory Database / Factory Score

### 7.1 スコア軸（12軸・各0-10、総合は重み付け平均）

| 軸 | 正準名（案） | 主データ源 | 更新トリガー |
|---|---|---|---|
| 品質 | SCORE_QUALITY | 出货检验合格率、限度样遵守 | 出货检验(CN-INSP-060)確定時 |
| 納期 | SCORE_DELIVERY | 約束納期vs実績（打样・大货） | Shipment確定時 |
| コスト | SCORE_COST | 見積の相場乖離・値上げ頻度 | Quote登録時・改定時 |
| 対応速度 | SCORE_RESPONSE | RFQ/質問への応答時間（WeChatDigest応答含む） | 各返信の受領登録時 |
| 技術力 | SCORE_ENGINEERING | 図面理解・工程提案・首件一発合格率 | 首件确认(CN-PROD-020)判定時 |
| ODM能力 | SCORE_ODM | 私模実績・設計支援・打样品質 | Sample評価確定時 |
| 日本市場経験 | SCORE_JP_MARKET | 日本向け出荷実績・告示370号対応経験 | 资质调查・実地審査時（手動） |
| 不良率 | SCORE_DEFECT_RATE | ロット不良率・市場不良件数 | 検品確定・Complaint登録時 |
| CAPA実行力 | SCORE_CAPA | CAPA提出期限遵守・再発有無 | CAPA(CN-QUAL-040)クローズ時 |
| 無断変更履歴 | SCORE_CHANGE_DISCIPLINE | G-06発動回数・ECR事前申請率 | G-06発動時（即時大幅減点） |
| 転注リスク | SCORE_SUBCON_RISK | 実地審査所見・繁忙期の外注兆候 | 工厂实地审核・装柜监督時（手動） |
| 生産能力 | SCORE_CAPACITY | 申告産能vs実績・繁忙期遅延 | Lot完了時 |

- スコアはFactory（`FA-{NNNN}`）に紐付き、**案件別実績（project別スナップショット）と累積スコアを分離**して保存する（1案件の事故で全評価が消えない/隠れないように）。
- 減点イベントの非対称性: G-06（無断変更）とCRITICAL不良は即時・大幅減点、回復は連続N案件の無事故でのみ緩やかに回復（自動回復させない）。
- 【現実性メモ M4】稼働初期は実績データが無く12軸の大半が空になる（04-critical-review §1-4 と同旨）。Phase 1 は **手動5軸（品質/納期/対応/日本経験/転注リスク）をCN_OFFICEの実査所見で入力**し、自動軸はデータが3案件貯まった軸から順次有効化する。
- 【現実性メモ M5】転注リスクの自動検知は現実には不可能（04 §5-15）。本軸は「実地審査・装柜監督・首件照合での人的所見」を記録する軸であり、AIは兆候（納期の不自然な短縮、産地の異なる材質報告等）のフラグ提示までに限定する。

### 7.2 FRISK_*（FactoryRisk）との連動

Factory Score は Project DNA の FactoryRisk 推定入力となり、FRISK_* が検品密度・監査要否を自動導出する（派生ロジックはDNAコードをキーにする — Governance §4）。

| FactoryRisk | 該当目安 | 検品密度（InspectionPlan既定） | 監査要否 | その他 |
|---|---|---|---|---|
| FRISK_TRUSTED | 総合8.0+ かつ 直近1年G-06ゼロ | 出货检验のみ（AQL通常検査） | 2年毎または重大変化時 | 首件は写真確認可 |
| FRISK_NORMAL | 総合6.0+ | 出货检验 + 首件現物確認 | 年1回 | — |
| FRISK_NEW | 取引実績 <3案件 | 上記 + 生产前确认の現地立会 + 中間抜き打ち1回 | **初回発注前に実地審査必須** | 初回は試产必須 |
| FRISK_HIGH | 総合<5.0 または G-06/CRITICAL履歴あり | 上記 + IPQC報告週次提出 + 出货検品を厳格検査（Tightened） | 案件毎 | 新規RFQ配信の既定候補から除外（人間が明示選択した場合のみ可） |

- FRISK降格（例: NORMAL→HIGH）は自動、昇格は人間承認（C_HUMAN_DECISION）。降格時は進行中案件のInspectionPlanを再生成し、差分をWeChatDigestで工場へ通知はしない（内部管理情報のため。工場に伝えるのは検品方式の変更のみ）。

## 8. Change Control 運用（無断変更の検知と ECR）

### 8.1 無断変更（未经批准变更）の検知手段（3層防御）

| 層 | 手段 | 実施Task | 検知対象 |
|---|---|---|---|
| 1. 首件比較 | 首件 vs 黄金样+規格書の全項照合（寸法実測・重量・材質色調・Logo・包装）。AIが写真差分候補を提示し人間が判定 | CN-PROD-020 | 材質/工程/色/構造の量産前変更 |
| 2. 抜き打ち検品・実査 | 予告なし工程訪問（FRISK_NEW/HIGHは必須）、装柜監督時の開箱照合、中間抜取の重量・寸法測定（重量は材質・肉厚変更の最良の代理指標） | CN-QUAL-050, CN-LOGI-020 | 量産中の材料すり替え・転注・工程省略 |
| 3. BOM・書類照合 | 材質報告のロット番号/鋼厂とBOM申告の突合、涂料牌号の照合、供应商発票名義の確認 | CN-SPEC-020, CN-INSP-060 | 供应商変更・回収料使用・牌号変更 |

- 疑義発生時のフロー: 検知者が「無断変更疑い」を起票 → **G-06 が即時発動し ShipmentRelease をBLOCK**（Governance §9）→ 工場に事実確認（WeChatDigestの変更点欄で通知+Excel回答様式送付）→ (a)事実であればECR事後申請+是正（Score大幅減点、10.3条の費用負担）、(b)誤検知であれば解除記録を残しBLOCK解除。**解除は必ずApproval記録を伴う**（人間でも記録なしに突破不可）。
