## 0. 本書の位置づけと用語

### 0.1 位置づけ

本書は Layer 1（Universal Core：カテゴリーを知らない共通基盤）側の品質「機構」と、Layer 2（Category Rule Pack：カテゴリーごとの設定データの束）が参照する**カテゴリー非依存の品質パラメータ既定値**を定義する。

1. Quality Tier（品質等級：Q1_ESSENTIAL〜Q4_LUXURY の4段階品質レベル）は、**属性・カテゴリーと独立したパラメータセット**である（§1）。
2. カテゴリー固有の中身（CTQの具体名・試験方法・欠陥限度の個別値）は、すべて 18番の Rule Pack データ（CTQ / Test Plan / Quality Standard / Inspection Template の payload）として供給される。本書はその**器（テンプレート構造）と Tier 別既定値**を設計する。
3. 18番 §2.3 の注記「正式な外観基準・AQL体系は16番を正とする」に基づき、**本書の Tier パラメータ値が正**であり、18番 §2.3 の初期例示値は本書 §1.2 の値へ読み替える（差分は §1.5 に明記）。
4. 本書に登場するタンブラー等の具体商品・具体数値は、Governance §0-2 に基づき**すべて「例でありシステム仕様ではない」**。

### 0.2 用語（初出定義・§14準拠）

- Quality Tier（品質等級：Q1〜Q4 の4段階品質レベル。Governance §4 正準コード）
- CTQ（重要品質特性：品質判断の重要基準）
- AQL（抜取検査基準：ロットから抜き取る数と合否判定数の規格。ISO 2859-1 ≒ JIS Z 9015 ≒ GB/T 2828.1）
- Ac/Re（合格判定数/不合格判定数：抜取サンプル中の不良がAc個以下なら合格、Re個以上なら不合格）
- FIXED MINIMUM（絶対最低基準：安全・法令・重大機能・虚偽表示防止に関わるため、Quality Tierでは緩和できない基準）
- Quality Dimension（品質次元：Safety安全 / Functional機能 / Durability耐久 / Appearance外観 / Sensory官能 の5分類。01番 §6）
- LimitSample（限度見本：外観の許容限度を現物で示す見本。Governance §1 正準語）
- Traceability（トレーサビリティ：材料・部品・工程・ロットを遡って特定できる記録体系）
- IPQC（工程内検査：生産途中で行う検査。Governance §1 正準語）
- DUPRO（中間検品：生産中盤に行う抜き打ち現物検査。During Production Inspection の略）
- Claim（性能主張：顧客・消費者に約束する性能の言明。例「漏れない」「保温6時間」。§7で構造化）
- 景品表示法（誇大表示の規制：性能表記には合理的根拠が必要。根拠なき優良表示は優良誤認）

## 1. Quality Tier 詳細基準（カテゴリー非依存パラメータセット）

### 1.1 設計原則 — Tierは「強度のツマミ」であり商品を知らない

1. Tierパラメータは**カテゴリー・属性から完全に独立**した数値・区分のセットである。「タンブラーのQ3」「家電のQ3」という定義は存在しない。
2. 適用基準は Rule Engine（18番 §2）が `属性×Tier` で合成する。Rule Pack の各 Rule Record は `tier_scaling`（Tier別強度値）に本§1.2 のパラメータIDまたは値を参照し、Step(c) で該当Tier列が選択される。
3. `priority_class = SAFETY / REGULATORY` の行は全Tier同値（FIXED MINIMUM）であることをスキーマで強制する（18番 §1.4 と同一の構造保証。§2）。
4. Tier確定は C_HUMAN_DECISION（人間決定：AIは推奨のみ）。Task は JP-QUAL-020（10番）。

### 1.4 Rule Engine との合成（属性×Tier）

- Tierパラメータは Rule Engine Step(c)（18番 §2.1）で適用される「列選択の入力」であり、**単独ではルールを構成しない**。実際の検査項目・試験・欠陥限度は Rule Pack（Category＋属性由来ルール）が供給し、Tierはその強度（AQL・抜取数・係数・要否）だけを決める。
- 合成後の矛盾は 18番 §2.4 の決定表に従う。特に SAFETY/REGULATORY 系は**常に最も厳しい方を採用**、APPEARANCE/SENSORY 系はTier準拠。
- DNA他軸との重畳（すべて「厳しい方優先」で合成。Tierとは独立の加算要素）:
  - ProductRisk＝PRISK_HIGH/CRITICAL → 検品密度増強・報告週2回（10番 R-08。AQLは§4.4の厳格検査へ切替）
  - BrandImpact＝BIMP_HIGH/CRITICAL → LimitSample・外観基準Task・品質コスト提示を必須生成（10番 R-10）。BIMP_CRITICAL は QT-04 を1段引き上げ（II→III）
  - FactoryRisk＝FRISK_* → 検品ステージ追加・厳格検査（12番 §7.2 の表を正とし、§4.5 で統合）

## 2. FIXED MINIMUM（Tierで緩和不可の絶対最低基準）

### 2.1 4領域の判定基準

ある品質項目が FIXED MINIMUM に該当するかは、カテゴリーではなく**次の4判定**で決める。1つでも該当すれば FIXED MINIMUM（Rule Record の `priority_class` を SAFETY または REGULATORY にする）。

| 領域 | 判定基準 | 例（※例でありシステム仕様ではない） | 不適合時のDefect |
|---|---|---|---|
| Safety（安全） | 不適合が人身・健康被害（怪我・火傷・誤飲・感電・有害物質曝露）につながり得る | 鋭利バリ、禁用物質（重金属・回収料）、小部品脱落 | CRITICAL |
| Legal Compliance（法令適合） | 法規（食品衛生法・電安法・電波法・家品法等）の規格・表示・手続に関わる。Regulatory Engine（13番）が REQUIRED/該当と判定した項目 | 溶出試験適合、PSEマーク、家品法表示義務項目 | CRITICAL |
| Critical Function（重大機能） | その商品の存在意義である機能の喪失（Rule Pack CTQ で `defect_severity=CRITICAL` と定義された機能） | 断熱容器の真空不良（保温しない）、密閉容器の漏れ、充電器の不充電 | CRITICAL |
| False Label Prevention（虚偽表示防止） | 表示・訴求（Claim）と実性能・実仕様の不一致（容量偽装・性能未達・材質相違・原産国誤表記） | 「保温6時間」表示で実測未達、容量表記と実容量の乖離 | CRITICAL（表示済みの場合）/ MAJOR（出荷前検出） |

### 2.2 構造的保証と Rule Engine マージ規則との接続

1. **登録時強制**: `priority_class=SAFETY/REGULATORY` の Rule は `tier_scaling` 4値が同一でなければ登録拒否（18番 §1.4）。「Q1だから溶出試験を省く」という設定は**作れない**。
2. **マージ時強制**: 同一 topic_key（対象キー：同じ事柄を指すルールの正規化キー）で基準値が競合したら**常に最も厳しい方を採用**（18番 §2.4 第1行）。属性由来の厳格値がカテゴリー既定・Tier値より優先されうる。
3. **緩和UIの遮断**: §5 の品質⇄コスト可視化・§6 の顧客選択肢に、FIXED MINIMUM 項目は**緩和選択肢として一切表示しない**。顧客文言は 11番既定の「どのレベルでも、安全と法律に関わる項目は同じ厳しさで必ず確認します」を全Tier選択画面に固定表示。
4. **Gate接続**: Legal Compliance 系は G-03（Regulatory=BLOCKED→停止）、検出済み CRITICAL は G-04/G-05、無断の材質・工程変更は G-06 に接続（Governance §9）。

### 2.3 FIXED MINIMUM 固定行テンプレート（Quality Tier表への組み込み形式）

QualityStandard 生成時、Tier別基準表の先頭に次の**固定行ブロック**を必ず挿入する（14番 §4-3 の引き継ぎを一般化。個別の中身は Rule Pack／Regulatory Engine が供給）。

| 固定行（テンプレート） | 検査方式 | 供給元 |
|---|---|---|
| 法規適合試験（溶出・電気安全・有害物質等、該当分） | ロット初回・材料/工程変更時に第三者試験。成績書を Document 保存 | Regulatory Engine（13番）＋Rule Pack REG/TST |
| 重大機能の全数保証項目（例: 気密100%全検） | 全数検査（工場ライン）＋出荷検品で抜取再確認。不適合=CRITICAL | Rule Pack CTQ（defect_severity=CRITICAL） |
| 禁用物質・材質同一性 | 材質証明ロット照合（全Tier）。無断変更検知は G-06 | Rule Pack FQ/QS＋ECR運用 |
| 法定表示・警告表示 | 全数目視（表示の有無）＋版下承認記録 | Regulatory Engine 表示リスト |
| Claim整合（表示性能＝実測性能） | Claim Ledger（§7.3）の実証記録が APPROVED であること | 本書 §7 |

### 2.4 試験条件の一本化ルール（引き継ぎ4への回答）

同一CTQに「法定表示値の測定」と「工場出荷試験」の2文脈がある場合（例: 保温効力）、次で一本化する（カテゴリー非依存の一般規則）:

- **表示値（家品法等の法定表示・Claim根拠）** = 規程・規格に準拠した測定（第三者または規程準拠の社内測定＋記録）を正とする。値は景品表示法の合理的根拠資料を兼ねる。
- **工場出荷試験** = 表示値に対する**管理値**（表示値＋安全マージン）で運用する。工場試験の合格＝表示値保証ではなく、管理値逸脱＝表示値再検証のトリガー。
- 両者は Rule Pack Test Plan 上で同一 `method_ref` 系列・別 `stage`（SAMPLE=表示値確定 / MASS=管理値監視）として登録し、Rule Engine の重複統合（18番 §2.4「試験の重複」）で二重計上を防ぐ。

## 3. 外観基準テンプレート

### 3.1 A/B/C Surface 定義（カテゴリー非依存）

Surface（見え面等級）はカテゴリーを問わず**使用時の可視性**で定義する。各カテゴリーの具体的な面割当は Rule Pack Quality Standard の payload（`target`）で供給する。

| 等級 | 定義（テンプレート） | 割当例（※例。タンブラー＝12番 §5-4.2 と整合） |
|---|---|---|
| A面 | 通常の使用・陳列で**常に目に入る面**（正面・ブランド表示面・上面） | 杯身正面（Logo面）・杯口外圈 |
| B面 | 使用中に**時々見える面**（背面・側面・底面外周） | 杯身背面・杯盖上表面 |
| C面 | 通常**見えない面／機能優先の面**（底裏・内部・内壁） | 杯底・杯盖内側・内胆内壁（機能不良のみ管理） |

- 面割当は GoldenSample 承認時に写真上でマーキングして確定し、QualityStandard に添付する（面割当の曖昧さが検品紛争の最頻原因）。
- C面でも**機能・安全に関わる欠陥（バリ・溶接不良・シール面傷）は外観扱いにしない**（Functional/Safety次元のCTQとして別掲）。

### 3.2 欠陥種×検査条件テンプレート構造

QualityStandard の外観ブロックは次の構造で生成する（Rule Pack QS payload `criteria_by_tier` の展開形）:

```yaml
appearance_standard:
  inspection_condition:        # QT-05/06/07 から展開
    distance_cm: 45
    seconds_per_face: 5
    lux: 600-800
    tools: 裸眼（放大鏡不使用）  # 拡大鏡使用時はその旨を基準に明記
  surfaces: [A, B, C]          # §3.1 定義＋写真マーキング参照
  defect_rules:                # 欠陥種ごとに1レコード
    - defect_type: SCRATCH     # 正準欠陥種コード（下表）
      surface: A
      max_size: {length_mm: 8, width_mm: 0.5}
      max_count: 3
      severity_if_over: MAJOR  # 限度超過時のDefect区分
      notes_ja/zh: ...
```

**正準欠陥種コード（8種・カテゴリー非依存）**: `SCRATCH`（傷）/ `DENT`（凹み・打痕）/ `COLOR_DIFF`（色差）/ `PRINT_MISALIGN`（印刷ズレ・カスレ）/ `BURR`（バリ）/ `GLUE_RESIDUE`（糊・接着剤残り）/ `GAP`（隙間・嵌合不良）/ `STAIN`（汚れ・異物付着）。カテゴリー固有の欠陥（例: 溶接ビード・縫製不良）は Rule Pack が欠陥種を**追加供給**する（8種は最小共通セット）。

## 4. Defect 分類と Inspection Plan

### 4.1 CRITICAL / MAJOR / MINOR 判定規則

Governance §3 正準enum（新設なし）。判定は次の順に上から評価し、最初に該当した区分とする。

| 順 | 判定質問 | 該当時 |
|---|---|---|
| 1 | 安全・健康被害の可能性があるか（§2.1 Safety） | **CRITICAL** |
| 2 | 法規不適合・法定表示の欠落/誤りか（§2.1 Legal） | **CRITICAL** |
| 3 | 重大機能の喪失か（Rule Pack CTQ で defect_severity=CRITICAL の機能） | **CRITICAL** |
| 4 | 表示・Claimと実物の不一致か（§2.1 False Label） | **CRITICAL**（表示済み）/ MAJOR（出荷前是正可） |
| 5 | 使用に支障がある、または通常の使用距離で明らかに気づく外観・機能不良か（返品・クレームにつながる） | **MAJOR** |
| 6 | 使用に支障がなく、注意して見れば気づく程度か | **MINOR** |

- 同一個体に複数不良がある場合は**最も重い1件でカウント**（個体単位）。ただし不良種別ごとの集計は報告書に残す（CAPA・Factory Score入力）。
- 外観限度（§3.3）の超過は既定で MAJOR（`severity_if_over` で欠陥種ごとに上書き可。例: C面軽微超過=MINOR）。
- 判定の曖昧域は LimitSample 照合で裁定し、裁定結果を QualityStandard 次版に反映（基準の自己改善ループ）。

### 4.2 AQL 運用の管理方式（Lot Size / Inspection Level / Sample Size / Ac/Re）

- 準拠規格: ISO 2859-1（≒ JIS Z 9015 ≒ GB/T 2828.1）。**正常検査・一次抜取**を既定とする。
- InspectionPlan 生成時にシステムが自動計算・固定する項目: `Lot Size（PO/LOT実数）→ 検査水準（QT-04）→ サンプル文字 → Sample Size → 各severityのAQL（QT-01/02）→ Ac/Re`。検品員が現場で変更することは禁止（変更はInspectionPlan再承認）。
- **CRITICAL は AQL 値を割り当てない**: 抜取サンプル中の CRITICAL は Ac=0/Re=1（1個発見で即ロット不合格＝判退）とし、かつ Rule Pack が全数検査を指定する項目（例: 気密）は抜取の外で100%実施する。
  - 根拠: 業界慣行では CRITICAL に AQL 0.65 等を割り当てる例もあるが、AQL 0.65 は n=80 で Ac=1（=CRITICAL 1個許容）となり、§2 FIXED MINIMUM（安全不良ゼロ許容）と矛盾する。よって本システムは **CRITICAL=Ac0固定**を正準とし、AQL数値はMAJOR/MINORにのみ使用する。
- 抜取サンプルは同一サンプルで CRITICAL/MAJOR/MINOR を同時判定（3回抜かない）。合否はseverityごとに独立判定し、**1つでも不合格なら判退**。

**参照表（一般検査水準II・正常検査・一次抜取の代表行。※規格表の抜粋であり、実装はISO 2859-1全表を保持する）**

| Lot Size | サンプル文字 | n | AQL 0.65 | AQL 1.0 | AQL 1.5 | AQL 2.5 | AQL 4.0 | AQL 6.5 |
|---|---|---|---|---|---|---|---|---|
| 281–500 | H | 50 | Ac0/Re1 | Ac1/Re2 | Ac2/Re3 | Ac3/Re4 | Ac5/Re6 | Ac7/Re8 |
| 501–1,200 | J | 80 | Ac1/Re2 | Ac2/Re3 | Ac3/Re4 | Ac5/Re6 | Ac7/Re8 | Ac10/Re11 |
| 1,201–3,200 | K | 125 | Ac2/Re3 | Ac3/Re4 | Ac5/Re6 | Ac7/Re8 | Ac10/Re11 | Ac14/Re15 |
| 3,201–10,000 | L | 200 | Ac3/Re4 | Ac5/Re6 | Ac7/Re8 | Ac10/Re11 | Ac14/Re15 | Ac21/Re22 |

（検証: Lot 1,000・水準II → n=80、MAJOR AQL1.0 Ac2/Re3、MINOR AQL2.5 Ac5/Re6。12番 §8.3 の Vertical Slice 実例（Q3案件）と一致。）

### 4.3 Tier別デフォルトと根拠

| Tier | 水準 | MAJOR/MINOR AQL | 根拠 |
|---|---|---|---|
| Q1_ESSENTIAL | 一般検査水準I | 4.0 / 6.5 | 配布用・低単価。検品コストを製品単価に対して非過大に保つ（水準Iは同ロットで抜取数約1/2）。ただしCRITICAL=Ac0・FIXED MINIMUMは不変のため「安全は同じ・見た目の許容だけ広い」状態を作る |
| Q2_STANDARD | 一般検査水準II | 2.5 / 4.0 | ISO 2859-1 の標準運用（水準IIが既定）。一般消費財の商慣習上の標準AQL（2.5/4.0）と一致し、工場側の受入れ・見積前提とも整合しやすい |
| Q3_PREMIUM | 一般検査水準II | 1.0 / 2.5 | 自社ブランド販売品。外観クレームがブランド毀損に直結するため MAJOR を厳格化。水準はIIのまま（抜取数を増やすより合格判定を厳しくする方が検品工数対効果が高い） |
| Q4_LUXURY | 一般検査水準III | 0.65 / 1.5 | ギフト・高価格帯。発見力（抜取数）と判定（AQL）の両方を強化。水準IIIは同ロットで抜取数約1.6倍となり、低い不良率の検出力が上がる |

### 4.4 100%検査への切替条件・厳格/緩和切替

| 切替 | 条件（いずれか成立で発動） | 内容 |
|---|---|---|
| **100%（全数）検査** | (1) Rule Pack が全数指定する FIXED MINIMUM 項目（例: 気密・通電・検針） (2) 抜取で CRITICAL を1個でも発見（当該ロット全数選別＋原因確定まで次ロットも全数） (3) 判退後の再提出ロット（工場全数返工→再検品） (4) 同一不良でのロット判退が2回連続 (5) 市場クレーム（Complaint）でロット起因が疑われる場合の在庫・未出荷分 | 全数選別は工場実施＋商社/事務所が選別後ロットへ通常抜取を再実施（選別の実効性確認）。費用は責任区分に従う |
| **厳格検査（Tightened）** | ISO 2859-1 の切替規則: 連続5ロット中2ロット判退。加えて本システム固有: FRISK_HIGH（12番 §7.2）/ G-06（無断変更）発動後の再開初ロット / PRISK_HIGH以上でTierがQ1（R-08との合成） | AQLを1段厳格化（例: MAJOR 2.5→1.5）またはAc/Reを厳格側の規格列で運用 |
| **通常復帰** | 厳格検査で連続5ロット合格、かつ是正（CAPA）クローズ | 通常検査へ復帰（自動。復帰もAuditLogに記録） |
| **緩和検査（Reduced）** | 連続10ロット合格・FRISK_TRUSTED・ECR/G-06なし・**人間承認（C_HUMAN_DECISION）** | 抜取数を規格の緩和列へ。**FIXED MINIMUM全数項目は緩和対象外**。1ロットでも不合格で即通常へ戻す |

### 4.5 検品ステージ構成と FRISK 連動（InspectionPlan の組み立て）

InspectionPlan は次の合成で生成する（すべてデータ駆動。カテゴリー分岐なし）:

```
InspectionPlan = Rule Pack Inspection Template（項目・方法・severity）
              × Tierパラメータ（QT-01〜26: 密度・頻度・主体・報告）
              × FRISK連動表（12番 §7.2 を正とする: TRUSTED=出荷検品のみ〜HIGH=IPQC週次+厳格検査）
              × R-08（PRISK_HIGH/CRITICAL: 検品密度増強・報告週2回）
```

- ステージ: IPQC（工程内検査）→ FirstArticle（首件）→ DUPRO（中間検品）→ PreShipmentInspection（出荷検品）。各ステージの要否・頻度は QT-12〜15 と FRISK 表の**厳しい方**。
- 出荷検品は G-05（検品未完了/FAIL未処理→ShipmentRelease停止）の証跡入力。検品報告（QT-26）と判定（PASS/判退）を登録して初めて SHIPMENT_READY の判定材料になる。
- **試験用サンプルの織り込み**（引き継ぎ6）: TestPlan 確定時、システムは `Σ(各試験の必要数×安全率1.5)` をサンプル発注数量（JP-SMP系Task）へ自動加算し、RFQ・PO数量に反映する（A_FULL_AUTO）。

## 5. 品質⇄コスト可視化

### 5.1 原価構成要素×品質パラメータ対応表

品質パラメータの増減がどの原価要素を動かすかの対応（概算エンジンの係数表。係数は初期値であり、Quote実績で案件・工場ごとに校正する）。

| 原価構成要素 | 影響する品質パラメータ | 感度の初期値（対 製品原価%） |
|---|---|---|
| 材料・部材グレード | Rule Pack CTQ 目標値（材質・肉厚等）、QT-23（グレードロック） | 項目により +3〜15%（Rule Packが係数供給） |
| 加工・工程精度 | 外観限度（§3.3）、GAP/印刷精度 | 限度1段厳格化ごとに +1〜3%（不良率・手直し率上昇分） |
| 検査工数（工場内） | QT-01〜09（AQL・抜取数・全数項目） | AQL1段厳格化 +0.5〜1.5% / 全数検査項目追加 +1〜3% |
| 検品費（商社側・第三者） | QT-14〜15（DUPRO・実施主体）、QT-26（報告） | 現地検品1回 = 固定費（人日単価×日数）。ロット数で割って%換算 |
| 試験費 | QT-09/16（係数）、Rule Pack Test Plan（lt_cost_range） | 試験リスト積算（13番 §3.2 形式の実額） |
| 包装材・梱包工数 | QT-19〜21 | 個装1段強化 +3〜8% / 輸送試験1段 +0.5〜1% |
| 管理・記録コスト | QT-22〜24（Traceability）、QT-25（報告） | 深度1段 +0.5〜2% |
| 品質保証引当（クレーム期待損） | Tier全体（不良率期待値） | Tierを下げると顕在化: Q1運用時 +1〜3%相当のクレーム期待損を内部原価に計上（顧客説明にも使用） |

### 5.2 概算ロジック

```
ΔCost%（ある品質項目の緩和/強化） = Σ_i（対応する原価要素iの感度 × 変更段数）
Tier間差 = Σ（QT-01〜26 の該当Tier列差分に対する ΔCost% 合計）＋ Rule Pack個別項目差
```

- 表示は**レンジ**（例: +3〜5%）で行い、確定額は Quote 取得後に実額へ置換する（G-15 の「概算」明示原則と同じ思想）。
- 提示単位は2種類: (a) 項目単位「この項目を緩和すると −X% / 強化すると +Y%」（JP-QUAL-040、A_FULL_AUTO）、(b) Tier単位「標準→ブランド重視で 合計 +Z%」。
- **情報遮断**（Governance §8）: 顧客に見せる%・金額は**顧客見積（Quotation）ベース**で計算する。工場原価・粗利は絶対に表示しない。Export帳票にも同一ルール。
- FIXED MINIMUM 項目は緩和候補リストから構造的に除外（§2.2-3）。強化方向のみ提示可（例: 法定試験に加えて追加保証試験）。

### 5.3 顧客4択→内部Tier変換表

顧客には AQL/CTQ を見せず4択で提示し（11番 STEP 6 と同一文言系）、内部で Tier へ変換する。

| 顧客表示（4択） | 顧客向け説明（平易・§14準拠） | 内部Tier | 想定用途シグナル |
|---|---|---|---|
| コスト重視 | 配布用など、コストを最優先。安全と法律のチェックは同じ厳しさで行います | Q1_ESSENTIAL | ノベルティ・販促配布 |
| 標準 | 一般的な販売品質。通常の使用で問題ないレベルを確認します | Q2_STANDARD | 低〜中価格帯の販売 |
| ブランド重視 | 自社ブランド販売向け。外観・使い心地を重点チェックします | Q3_PREMIUM | 自社ブランド・EC/店頭 |
| プレミアム | ギフト・高価格帯向けの最上位チェック。開封した瞬間の印象まで確認します | Q4_LUXURY | ギフト・百貨店・旗艦商品 |

- 選択時に各選択肢へ**概算コスト差**（Q2比 −X%/+Y%。§5.2(b)）と**推奨バッジ**（§6の推薦結果）を併記する。
- 顧客選択と推薦が食い違う場合は理由付き再提案を表示するが進行は止めない（11番 §4 の運用と整合）。最終確定は JP-QUAL-020（C_HUMAN_DECISION）。
- EXP_PROFESSIONAL には Tier詳細基準（本書 §1.2 の表）を開示して選択させる（11番 §9。抽象化がむしろ障壁のため）。ただし情報遮断は同一適用。

| 分類 | B_AI_DRAFT（推奨生成=JP-QUAL-010）→ C_HUMAN_DECISION（Tier確定=JP-QUAL-020）。01番 §1 の「人間承認必須」に準拠 |

### 6.2 推薦ロジック（スコア方式・決定表）

カテゴリー名で分岐しない。以下はすべて属性・DNA・価格帯（Rule Pack が供給するカテゴリー価格レンジに対する相対位置）で評価する。

| 要素 | 評価 | Tierスコアへの寄与 |
|---|---|---|
| 価格ポジション | 販売価格がカテゴリー価格レンジのどの分位か（Rule Pack供給。無償配布は最下位扱い） | 下位1/4 → Q1〜Q2 / 中位 → Q2〜Q3 / 上位1/4 → Q3〜Q4 |
| チャネル | 配布=−1 / EC・店頭=0 / ギフト・百貨店・法人贈答=+1 | 段階加算 |
| BrandImpact | BIMP_LOW=−1 / MEDIUM=0 / HIGH=+1 / CRITICAL=Q3を下限にクランプ | 段階加算＋下限 |
| リピート・展開意図 | 継続販売・シリーズ化意図あり → +0.5（初回クレームの将来影響大） | 加算 |
| ProductRisk | Tierには直接加算しない（検品密度はR-08で別途増強）。ただし PRISK_CRITICAL 時は Q1 推奨を出さない（Q2下限） | 下限 |
| 顧客予算制約 | 予算が推奨Tierのコストと不成立 → 1段下＋「差分リスクの説明」を理由文に必ず含める | 調整 |

- 合成: 基準Tier（価格ポジション）に加算値を適用し Q1〜Q4 にクランプ。**推奨は常に1個＋代替1個**（例: 推奨Q3・代替Q2＋差分説明）を出す。
- 出力の一部として、Tierに依らない FIXED MINIMUM 一覧を必ず添付し、「この部分は選択の対象外」であることを顧客文言で明示する。

## 7. ★性能主張（Claim）アーキテクチャと IR-04 解決案

### 7.1 一般化 — Claim⇄CTQ⇄試験⇄表現規制のリンク（カテゴリー非依存）

IR-04（フタ仕様の三文書不整合）の根本原因は「**顧客に見せた性能表現**」「**仕様として選んだ構造**」「**実施する試験**」「**法規上の表現可否**」が別々の文書で管理され、リンクが無かったことである。よって解決は個別修正ではなく、次の**Claimオブジェクト**を Layer 1 に導入することで行う（カテゴリー非依存の一般機構）。

```yaml
claim:                              # 性能主張1件 = 1レコード
  claim_id: {ProjectID}-CLM-{NN}    # ※TYPEコードCLM追加はGovernance変更提案-1
  claim_text_ja: バッグに入れても安心（漏れにくい）
  claim_origin: PROPOSAL            # 発生源（提案文/顧客要求/商品ページ案/パッケージ版下）
  linked_ctq: RP-xxx-CTQ-xx         # 対応するCTQ（Rule Pack供給）。CTQ選択肢の1つに紐付く
  linked_spec_field: lid_type       # 性能を実現する仕様項目（SpecField）
  required_tests: [RP-xxx-TST-xx]   # このClaimの根拠となる試験（合格が実証条件）
  regulatory_constraints:           # 表現規制（景品表示法=不実証広告規制、家品法表示等）
    - 景品表示法: 合理的根拠資料（試験成績書）保管が条件
  evidence_status: PENDING          # Approval enum流用（PENDING/APPROVED/REJECTED/CONDITIONAL）
                                    # APPROVED = 試験合格＋REG確認済み（実証済み）
  factory_acknowledgement: true/false # 工場が当該性能を承諾しているか（非承諾の明示記録を含む）
  allowed_expressions_ja: [...]     # 使用可能な顧客向け文言（実証レベルに対応）
  forbidden_expressions_ja: [...]   # 禁止文言（工場非承諾・未実証・法規制約）
```

**運用ルール（Layer 1 機構）**

| # | ルール |
|---|---|
| 1 | Proposal・商品ページ案・パッケージ版下に性能表現が含まれる場合、AIがClaim候補を自動抽出し登録する（B_AI_DRAFT） |
| 2 | Claimは必ず `linked_spec_field`（構造）と `required_tests`（試験）に接続していなければ APPROVED にできない（宙に浮いた約束の禁止） |
| 3 | **Claim競合検知**: `factory_acknowledgement=false`（工場の非承諾記録）と顧客向け表現が併存したら即時WARN（IR-04はまさにこの状態）。→ Governance変更提案-2（G-16）で Soft Gate 化を起案 |
| 4 | `evidence_status≠APPROVED` のClaimを含む顧客向け表現物（商品ページ・パッケージ）の承認はWARN付きとし、量産用版下承認（印刷発注）の前までに実証完了を必須とする |
| 5 | CTQの選択肢（§7.2形式）を変更したら、リンクする全Claimを自動で再評価（PENDING に差し戻し）し、顧客向け表現の再確認Taskを生成する |
| 6 | Claimの実証記録（試験成績書）は景品表示法の合理的根拠資料としてDocument保存し、§2.4 の表示値測定と同一SoTにする |

### 7.2 (a) 密閉性能の CTQ 選択肢構造化（テストケース: タンブラー ※例でありシステム仕様ではない）

「密閉性能」を単一のON/OFFではなく、**段階化された選択肢体系**として Rule Pack CTQ に構造化する。各選択肢が「発火する試験・許容される表現・コスト影響」を持つ。この形式自体はカテゴリー非依存（例: 防水等級・耐荷重クラス・保温クラス等も同形式）。

**SpecField `lid_type` の選択肢体系（例）**

| 選択肢コード | 構造（例） | 発火する試験（Rule Pack Test Plan） | 許容されるClaim表現（実証後） | 禁止表現・必須注記 | コスト影響目安（対Q2防溅比） |
|---|---|---|---|---|---|
| LID_SEAL_SCREW | 完全密閉スクリュー式（ねじ込み＋パッキン） | 倒置漏れ（満水・倒置30分）＋横倒し振動（輸送模擬）＋温度差加圧（熱湯密閉時の内圧） | 「フタを閉めれば横倒し・逆さでも漏れにくい」「バッグに入れても安心」 | 「完全に漏れない」等の絶対表現は禁止（景表法。試験条件付き表現のみ） | +8〜15%（パッキン精度・金型・全数気密相当検査） |
| LID_FLIP_LOCK | ロック付フリップ式 | 横倒し漏れ（満水・水平30分）＋開閉耐久＋ロック強度 | 「横にしても短時間なら漏れにくい」「片手で開けられて持ち運びやすい」 | 「逆さOK」禁止。「長時間の横倒しは避けてください」注記必須 | +4〜8% |
| LID_SLIDE_SPLASH | 防溅スライド式／推盖式（飛散防止） | 水平静置渗漏（満水・水平30分。12番 5.3 と同一）のみ | 「デスクでの飛び散り・ホコリを防ぐ」 | **「密閉」「漏れない」「バッグに入れても安心」全面禁止**。「傾けると漏れることがあります」注記必須（12番 5.3「防漏表記禁止」と整合） | 基準（±0%） |
| LID_NONE | フタなし／簡易載せフタ | なし（防塵のみ） | 「ホコリよけ付き」 | 持ち運び系Claim全面禁止 | −2〜5% |

- 各選択肢は `lid_material`（フタ材質）SpecFieldと連動し、**食品接触の溶出試験対象樹脂が選択肢で変わる**（例: Tritan系コポリエステル vs PP）。Regulatory Engine の試験リストは lid_material の確定値から生成する（§7.4-c3）。
- 選択肢は「顧客の用途回答（持ち歩き方）→ 推奨選択肢」のマッピングを Required Questions（Rule Pack）が持ち、A2 の質問（Q5相当）と接続する。

### 7.3 (b) 顧客向け表現ルール（景品表示法連動）

| # | ルール（カテゴリー非依存） |
|---|---|
| 1 | **表現は実証レベルに従属する**: 顧客・消費者向けの性能表現は、Claimの `allowed_expressions`（実証済み試験に対応した文言）からのみ選択できる。自由記述の性能表現はAIが検知しClaim候補化する |
| 2 | **試験条件付き表現の原則**: 絶対表現（「絶対漏れない」「割れない」）は全カテゴリーで禁止。「（条件）で（結果）」形式（例: 「満水で倒して30分置いても漏れないことを確認済み」）を標準とする。景品表示法の不実証広告規制（性能表記には合理的根拠が必要）対応 |
| 3 | **工場承諾との整合**: 工場が仕様書上で非承諾を明記した性能（例: 12番 5.3「不承诺倒置不漏」）は、承諾取得（ECR/仕様変更）まで当該Claimを REJECTED とし、顧客向け表現から自動除外する |
| 4 | **表示の二重化禁止**: パッケージ・商品ページ・取説の性能表記はすべてClaim Ledger（Claimの台帳）から生成し、文書ごとの手書き表現を禁止する（三文書不整合の再発防止そのもの） |
| 5 | **注意表記の自動付随**: 選択肢が下位性能の場合、必須注記（例: 「傾けると漏れることがあります」）をパッケージ版下チェックリストに自動追加する（False Label Prevention＝§2.1 第4領域） |

## 8. テストケース検証 — 同一商品・同一カテゴリーでの Tier 基準差

**※本節は全体がテストケースの例であり、システム仕様ではない**（Governance §0-2）。同一の350mlステンレス真空断熱タンブラーを、(A) 500円ノベルティ（Q1_ESSENTIAL適用例）と (B) 8,000円自社ブランド・ギフト品（Q4_LUXURY適用例）で比較する。ロットはいずれも1,000個。

| 項目 | (A) 500円ノベルティ（Q1） | (B) 8,000円ブランド品（Q4） |
|---|---|---|
| 内部Tier / 顧客表示 | Q1_ESSENTIAL /「コスト重視」 | Q4_LUXURY /「プレミアム」 |
| 検査水準・抜取数（Lot 1,000） | 一般検査水準I → n=32 | 一般検査水準III → n=125 |
| MAJOR 判定 | AQL 4.0 → Ac3/Re4 | AQL 0.65 → Ac2/Re3 |
| MINOR 判定 | AQL 6.5 → Ac5/Re6 | AQL 1.5 → Ac5/Re6 |
| CRITICAL | **Ac=0（両者同一・FIXED MINIMUM）** | **Ac=0（同一）** |
| 気密検査 | **100%全検（両者同一・FIXED MINIMUM）** | **100%全検（同一）** |
| 溶出試験・材質証明・禁用物質・法定表示 | **実施・全Tier同一（FIXED MINIMUM）** | **同一** |
| 外観検査条件 | 60cm・3秒/面・400lux | 30cm・10秒/面・600–800lux＋D65色確認 |
| A面 傷の許容（例） | L≤10mm・3本まで | L≤3mm・1本まで |
| 色差 | 目視で明らかでないこと | ΔE≤1.0＋ロット間色ブレ記録 |
| LimitSample | 不要 | 3点セット双方保管＋A面写真基準書 |
| 保温性能試験（機能） | 抜取3個/ロット（Rule Pack既定×1.0） | 抜取6個/ロット（×2.0）＋官能比較 |
| 耐久試験（開閉・落下等） | 既定サイクル×1.0 | ×2.0 |
| 首件・試作量産 | 首件写真確認 | 首件現物＋PilotRun＋初日立会推奨 |
| 中間検品・出荷検品 | 出荷時: 工場自検＋書類確認 | DUPRO 1回以上＋第三者/事務所検品＋二重確認 |
| 包装 | PE袋＋白盒・ISTA簡易 | ギフト化粧箱・全数外装検査・ISTA 2A相当＋開封体験チェック |
| Traceability | 出荷ロット単位（＋食品接触材の証明は必須=FIXED MINIMUM） | 全部材ロット対応表＋箱単位追跡＋グレードロック |
| 報告 | マイルストーンのみ・NG写真 | 週2回＋検品写真50枚＋動画＋見本照合写真 |
| 概算品質コスト差（対Q2比・§5.2） | 約 −3〜6%（＋クレーム期待損 +1〜3%を内部計上） | 約 +12〜25% |

**検証ポイント**: (1) 安全・法規・重大機能（気密・溶出・表示・CRITICAL=0）は両者で**完全に同一**＝FIXED MINIMUM がTier非連動であることが表で確認できる。(2) 差が出るのは Appearance/Sensory/Durability の強度と検品・報告・包装・追跡の密度のみ。(3) いずれの値もカテゴリー固有ロジックではなく、§1.2 のTier列＋Rule Pack供給値の合成で再現できる。

## 10. Governance変更提案（3件・未裁定）

### 提案-1: Project配下TYPEコードに `CLM`（Claim：性能主張）を追加

- 内容: Governance §2 のTYPEコード（RFQ/QT/QO/SMP/GS/ECR/PO/LOT/INS/SHP/CMP/CAPA/DOC）に `CLM` を追加し、性能主張を `{ProjectID}-CLM-{NN}` で採番する。
- 理由: §7 のClaimは表示・試験・仕様をつなぐ第一級エンティティであり、DOC流用ではIR-07型のID混雑・追跡不能を招く。Statusは新設せず既存 Approval enum（PENDING/APPROVED/REJECTED/CONDITIONAL）を流用する（A2②裁定の先例に従う）。

### 提案-2: Soft Gate `G-16 未実証Claim表現` の新設

- 内容: `gate_id=G-16 / type=SOFT / checkpoint=顧客向け表現物の承認（Proposal送信・商品ページ文言・パッケージ版下承認） / condition=evidence_status≠APPROVED のClaim、または factory_acknowledgement=false と矛盾する表現を含む / blocked_actions=なし（WARN付き進行可） / 補足=量産用版下承認（印刷発注）時点では未実証Claimの解消を必須とする（運用上はG-04 Critical Issue化で担保）`。
- 理由: IR-04の再発防止機構（§7.1 ルール3・4）に対応する既存Gateがない。A7引き継ぎの攻撃シナリオ（密閉約束と防漏表記禁止の併存のまま量産）を工程上流で検知する。

### 提案-3: Canonical Glossary への2語追加

- 内容: `Claim | 性能主張 | 性能宣称`、`DUPRO | 中間検品 | 中期验货` を Governance §1 正準表へ追加。
- 理由: Claimは§7で全文書横断の正準概念になる。DUPROは検品ステージ（§4.5）の正準語が現行Glossaryに欠落しており、A5の中国側Task（抜き打ち中間検品）との用語統一に必要。AQL・CTQは18番 §0.2 で初出定義済みのため本提案には含めない（採否は統合レビューに委ねる）。
