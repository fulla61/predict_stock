## 1. Regulatory Engine 仕様

### 1.1 設計思想 — 「候補の見落とし」が最悪の失敗

法規チェックにおける失敗モードの深刻度は非対称である。

| 失敗モード | 影響 | 設計上の扱い |
|---|---|---|
| 過剰検出（不要な法規を候補に挙げる） | REGの確認工数が増える | 許容（コスト） |
| **見落とし（適用法規を候補に挙げない）** | **販売停止・回収・行政処分・刑事罰・顧客の事業毀損** | **最悪の失敗。設計全体をこれの防止に最適化する** |

このため本Engineは次の運用を必須とする。

1. **カテゴリ別チェックリストの初版は人間専門家（REG + 外部専門家）が作成する。** AIがゼロから法規リストを生成することは禁止。
2. **AIの役割は「照合・変更検知・下書き」に限定**する: (a) 商品情報とチェックリストの照合、(b) チェックリスト外の兆候（新素材・新機能・訴求文言）を検知して `REVIEW_REQUIRED` にエスカレーション、(c) 法令・通知の改正情報の検知とREGへの通知（改正の解釈はしない）。
3. **迷ったら候補に含める（over-inclusion bias）。** 「該当可能性: 低」でも根拠付きで出力し、除外の最終判断はREGが行う。
4. チェックリストに存在しないカテゴリの商品は自動で `REVIEW_REQUIRED`（AIによる `NOT_APPLICABLE` 判定は禁止）。

### 1.2 入力（Regulatory Input Profile）

Requirement / Specification（SpecField）から抽出する。未確定項目は `UNKNOWN` として扱い、**UNKNOWNは「リスク無し」ではなく「判定不能→保守側判定」**とする。

| 入力項目 | 型/例 | UNKNOWN時の扱い |
|---|---|---|
| 商品カテゴリ | タンブラー / 家電 / 玩具 等 | REVIEW_REQUIRED |
| 材質（部位別BOM） | SUS304 / PP / シリコーンゴム / 塗装 | 食品接触・表示判定は保守側（該当扱い） |
| 用途 | 飲食用 / 装飾用 / 業務用 | 飲食用と仮定 |
| 対象年齢 | 一般 / 子供（未就学等） | 子供用の可能性ありとしてWARN |
| 食品接触の有無 | あり/なし | **ありと仮定** |
| 電源の有無・電圧 | なし / AC100V / USB / 電池 | 電気ありと仮定してWARN |
| 電波の有無 | BT/Wi-Fi/なし | ありと仮定してWARN |
| 訴求表現 | 保温6時間 / 抗菌 等 | 景表法チェック対象として収集 |
| 販売チャネル・販売者 | 顧客ブランド / ノベルティ | 表示義務者の判定に使用 |
| 原産国 | 中国 等 | 原産国表示チェック対象 |

### 1.3 出力（Regulatory Assessment）

出力は Project 配下の Regulatory エンティティ（01の§2）に記録し、`{ProjectID}-DOC-xx` として版管理する。

```yaml
regulatory_assessment:
  project_id: CI-2026-0001
  status: REVIEW_REQUIRED          # §3 正準enum
  candidates:                       # 適用法規候補（見落とし防止のため低該当も列挙）
    - law: 食品衛生法
      applicability: HIGH           # HIGH / CONDITIONAL / LOW
      basis: "食品接触あり（飲料用）→ 器具・容器包装に該当する可能性"
      expert_check: REQUIRED        # REQUIRED / RECOMMENDED / NOT_REQUIRED
  required_documents: [...]         # 必要書類候補
  required_tests: [...]            # 必要試験候補（項目・機関種別・LT・費用レンジ）
  required_labels: [...]           # 必要表示候補
  import_procedures: [...]         # 輸入手続候補
  rfq_requirements: [...]          # RFQ段階で工場へ要求する書類（§3.6）
  disclaimer: 固定文言（§6）
  checked_against: checklist_tumbler_v1.2   # 照合したチェックリストの版
  ai_notes: "チェックリスト外の検知事項（あれば）"
```

### 1.4 処理フロー

```
[Requirement/SpecField 更新] （SYSTEM: trigger）
   ↓
(1) Input Profile 抽出（AI）— UNKNOWN項目は保守側に補完しフラグ
   ↓
(2) カテゴリ別チェックリスト照合（AI）— 人間作成のchecklist最新版と突合
   ↓
(3) 候補生成（AI）— 法規候補+根拠+専門家確認要否、書類/試験/表示/輸入手続の候補リスト
   ↓
(4) 逸脱検知（AI）— チェックリスト外の素材・機能・訴求を検知したら理由付きで強制 REVIEW_REQUIRED
   ↓
(5) REGレビュー（人間）— 候補の採否・追加、外部専門家/所轄機関への確認要否を判断
   ↓
(6) Status確定（REG。BLOCKED解除・NOT_APPLICABLE確定は REG+MGR）
   ↓
(7) Gate Engine へ反映（SYSTEM）— G-03 / Readiness 判定（§4）
```

- Automation分類: (1)〜(4) = `B_AI_DRAFT`（ドラフトのみ）、(5)〜(6) = `C_HUMAN_DECISION`、(7) = `A_FULL_AUTO`。
- SpecFieldの材質・用途・対象年齢・訴求が変更されたら、Status を自動で `CHECKING` に戻し再照合する（`A_FULL_AUTO`、確定は人間）。

### 1.5 Status遷移と実行者（正準enumのみ使用・新設なし）

| 遷移 | トリガ | 実行者 |
|---|---|---|
| `NOT_CHECKED → CHECKING` | 案件作成 / Input Profile成立 / 関連SpecField変更 | SYSTEM/AI（自動） |
| `CHECKING → REVIEW_REQUIRED` | AI照合完了（候補あり）、またはチェックリスト外検知 | AI（自動、必ず根拠添付） |
| `REVIEW_REQUIRED → APPROVED` | REGが候補・試験計画・表示計画を承認（必要な外部確認完了） | **REG**（Approval記録必須） |
| `REVIEW_REQUIRED → NOT_APPLICABLE` | REGが「適用法規なし」と判断 | **REG + MGR**（二重承認。AIによる自動NOT_APPLICABLE禁止） |
| `REVIEW_REQUIRED → BLOCKED` | 重大な不適合・未解決の適法性疑義（例: 溶出試験FAIL、無認証の電気/無線） | **REG**（即時。理由必須） |
| `CHECKING → BLOCKED` | AIが明白な禁止事項を検知（例: 規制物質の使用宣言） | AI仮BLOCK → **REGが24h内に確定/差戻し** |
| `BLOCKED → REVIEW_REQUIRED` | 是正措置（再試験PASS・仕様変更ECR等）の提出 | **REG**のみ（G-03 Override不可原則の通り、解除はStatus変更でのみ実現） |
| `APPROVED / NOT_APPLICABLE → CHECKING` | 関連SpecField変更・法令改正検知・訴求文言変更 | SYSTEM/AI（自動差戻し。人間承認済み判定を自動で上書きするのではなく「再確認要」に戻すのみ） |

- 全遷移は AuditLog（Who/When/Before/After/Reason/Approval）必須。
- REGの代理承認者: MGR（Governance Pack §8 の代理ルールに従い、案件ごとに指名）。

### 1.6 チェックリスト管理（人間初版・AI照合限定）

| 作業 | 実行者 | 備考 |
|---|---|---|
| カテゴリ別チェックリスト初版作成 | REG + 外部専門家（行政書士・試験機関等） | 版管理（v1.0〜）。SoTはdocs/DB |
| チェックリスト改訂 | REG起案 → MGR承認 | 法令改正・新カテゴリ追加時 |
| 商品との照合・差分検知 | AI | 照合結果に checklist版数を必ず記録 |
| 法令改正のウォッチ（官報・省庁サイト等） | AI検知 → REG判断 | AIは「変わったかもしれない」までしか言わない |

## 2. カテゴリ別適用法規マトリクス（概要版）

凡例 — **高**: 原則該当（候補必須）/ **条**: 条件付き該当（条件をセルに記載）/ **低**: 通常非該当だが確認推奨。
※ 本表はチェックリスト初版作成のたたき台であり、**正式チェックリストはREG+外部専門家が確定する**。実務では最新の法令・通知を確認すること。

| カテゴリ＼法規 | 食品衛生法 | 電気用品安全法(PSE) | 電波法 | 消費生活用製品安全法 | 家庭用品品質表示法 | 景品表示法 | 知財（商標/意匠/特許） |
|---|---|---|---|---|---|---|---|
| 食品接触雑貨（タンブラー・食器・弁当箱） | **高**（器具・容器包装。樹脂はポジティブリスト） | 低 | 低 | 低（重大事故報告義務は全製品共通） | **条**（指定品目該当時: 例 まほうびん類） | **高**（性能訴求時） | **高**（OEM/ODM共通） |
| 電気製品（AC電源） | 条（調理家電の食品接触部） | **高**（特定/特定以外の区分判定） | 条（無線機能搭載時） | **条**（特定製品該当時＋長期使用製品） | 条（電気機械器具の指定品目） | **高** | **高** |
| 無線機器（BT/Wi-Fi搭載品） | 低 | 条（電源方式による。ACアダプタは高） | **高**（技適マーク必須） | 低 | 低 | **高**（通信性能訴求） | **高** |
| 玩具・子供用品 | **条**（乳幼児向け玩具は食品衛生法の「おもちゃ」規制） | 条（電動玩具の電源） | 条（無線玩具） | **条**（特定製品該当時。ST等任意規格も検討） | 条 | **高** | **高** |
| 繊維製品（アパレル・バッグ） | 低 | 低 | 低 | 低 | **高**（繊維製品品質表示規程: 組成・洗濯表示等） | **高** | **高** |
| 化粧品容器（中身なし容器のみ） | 低（食品接触なし。ただし食品兼用容器は高） | 低 | 低 | 低 | 条 | **高** | **高** |
| （横断）中身入り化粧品・医薬部外品 | — | — | — | — | — | — | **薬機法が別途必須** → 本マトリクス外。検知したら即 REVIEW_REQUIRED |

横断事項（全カテゴリ共通で候補に含める）:
- **関税法・関税定率法**: 輸入通関、知的財産侵害物品の水際規制、原産地虚偽表示物品の輸入禁止。
- **景品表示法の原産国告示**: 原産国の不当表示防止（「日本製風」の表記に注意）。
- **製造物責任法(PL法)**: 輸入者は製造業者等として責任を負い得る（法規手続ではないがリスク評価に必須）。
- 抗菌・除菌・消臭等の訴求 → 景表法+場合により薬機法抵触の検知対象。

## 3. ★タンブラー詳細マトリクス（Vertical Slice用）

対象: **ステンレス真空断熱タンブラー 350ml**（内面: ステンレス SUS304想定 / 外面: 粉体塗装 / パッキン: シリコーンゴム / フタ: PP樹脂）。原産国: 中国。日本国内で顧客ブランドとして販売。

> 注: 以下の判定・試験項目・費用は2026年1月時点の一般知識に基づく**候補と目安**である。実務では最新の法令・告示・検疫所運用・試験機関見積を必ず確認し、最終判断はREG＋外部専門家が行うこと。

### 3.1 適用法規の具体判定（候補+根拠+専門家確認要否）

| # | 法規 | 判定候補 | 根拠 | 専門家確認 |
|---|---|---|---|---|
| 1 | **食品衛生法**（器具・容器包装） | **該当: 高** | 飲料が直接接触する「器具」に該当。規格基準（食品、添加物等の規格基準・告示370号系）への適合が必要。**合成樹脂部分（フタPP）はポジティブリスト制度の対象**（使用可能物質・使用条件の適合確認）。**パッキンのシリコーンゴムは一般に「ゴム」として扱われ、ポジティブリスト対象範囲かは制度運用の確認が必要**（ゴムとしての規格基準は適用）。**金属部分（ステンレス・塗装面）は器具の一般規格**（着色料・鉛/アンチモン等の材質面の規制、飲食接触面の塗装の溶出）で確認 | **REQUIRED**（樹脂PL適合・シリコーンの扱い・塗装面の判定は試験機関/検疫所に確認） |
| 2 | **食品衛生法に基づく食品等輸入届出**（検疫所） | **該当: 高** | 販売用の「器具」の輸入は輸入届出の対象。届出→審査→（必要時）検査→届出済証の交付後に通関 | **REQUIRED**（通関業者+検疫所へ事前相談） |
| 3 | **家庭用品品質表示法** | **条件付** | 雑貨工業品品質表示規程の指定品目（例: まほうびん類=真空二重構造の保温容器）に**該当するかは構造・用途で判断が分かれる**（フタの密閉性・携帯用か卓上用か等）。該当すれば保温効力・容量・表示者名等の表示義務 | **REQUIRED**（消費者庁の運用・規程の適用範囲を確認） |
| 4 | **景品表示法** | **該当: 高**（訴求次第） | 「保温6時間」「保冷12時間」等の性能表示には**合理的根拠資料**が必要（不実証広告規制）。根拠なき表示は優良誤認 | RECOMMENDED（表示案確定時にREGレビュー必須） |
| 5 | **商標法・意匠法（＋不正競争防止法）** | **該当: 高**（確認必須） | 顧客ブランド名・ロゴの商標調査、既存タンブラーの登録意匠・周知形態との類否確認。侵害品は関税法の水際差止対象 | RECOMMENDED〜REQUIRED（弁理士。BrandImpact高案件はREQUIRED） |
| 6 | **関税法等（輸入通関・原産国表示）** | **該当: 高** | 通関手続、原産国の適正表示（景表法原産国告示とセット）。「MADE IN CHINA」の適切な表記 | RECOMMENDED（通関業者） |

該当候補外として明示（見落とし防止のため理由付きで記録）: 電気用品安全法（電源なし: 低）/ 電波法（無線なし: 低）/ 消費生活用製品安全法の特定製品（該非: 低。ただし重大製品事故報告義務は輸入事業者として適用あり）。

|---|---|---|---|---|---|

| （任意・訴求根拠） | 保温・保冷効力試験 | 家品法表示様式に準じた保温効力（例: 95℃±1℃の湯を入れ6時間後の温度）等。**景表法の合理的根拠資料を兼ねる** | 試験機関または社内測定+記録（表示義務該当時は規程の方法） | 1〜3週 | 2〜5万円 |

- 工場が保有する**日本の告示370号に基づく既存試験成績書**が有効活用できる場合がある（同一材質・同一グレード・試験日が新しいことが条件）。流用可否はREGが判断。

### 3.4 輸入手続フロー（食品衛生法・器具）

```
(1) 事前準備: 材質構成の確定・試験成績書の取得（3.2）・輸入者情報整備
   ↓
(2) 食品等輸入届出: 貨物到着前〜到着時に検疫所へ届出（通関業者経由が一般的）
   ↓
(3) 審査: 書類審査（材質・規格適合の確認。試験成績書の提出を求められる場合あり）
   ↓
(4) 検査: 必要に応じモニタリング検査/命令検査等（初回輸入・履歴なしは検査可能性が上がる）
   ↓
(5) 届出済証の交付 → 輸入通関（関税法手続） → 国内販売可
```

- 初回輸入は**検疫所への事前相談**を必須Taskとする（`JP-REG-xxx` としてA1のTask体系へ連携）。
- 実務では最新の検疫所運用・届出様式を確認すること。

### 3.5 タンブラー用 Status運用例（Vertical Slice）

| 時点 | Regulatory Status | 実行者 |
|---|---|---|
| 案件作成（0知識顧客の入力解析直後） | NOT_CHECKED → CHECKING | SYSTEM/AI |
| AI照合完了（本§3の候補一式を生成） | CHECKING → REVIEW_REQUIRED | AI |
| RFQ発行（法規は未確定のまま） | REVIEW_REQUIRED のまま進行（§4のSoft運用） | — |
| 工場書類+試験成績書レビュー完了・表示計画承認 | REVIEW_REQUIRED → APPROVED | REG |
| もし溶出試験FAIL・是正不能 | REVIEW_REQUIRED → BLOCKED（G-03発動） | REG |

### 3.6 RFQ段階で工場に要求すべき書類（Vertical SliceのRFQ生成に組込み）

A5の中国語RFQテンプレート・A1のRFQ Taskに、以下を**必須添付要求項目**として組み込む（中国語名は括弧内、A5の用語ルールに従い最終化）。

| # | 要求書類 | 目的 | 必須度 |
|---|---|---|---|
| 1 | 材質証明書（材质证明/不锈钢材质单・ミルシート） — 本体SUS・フタPP・パッキンシリコーンのグレード明記 | 材質の同定。試験計画とPL適合確認の前提 | 必須 |
| 2 | 過去の溶出試験成績書（针对日本食品卫生法・告示370号的检测报告） — 同一材質・発行日付き | 試験流用可否の判断、工場の日本対応力評価 | 必須（無ければ「無し」と回答させる） |
| 3 | 日本輸出実績（对日出口实绩: 品目・年・輸出先種別） | FactoryRisk評価・検疫所検査履歴の推定 | 必須 |
| 4 | 樹脂原材料のポジティブリスト適合宣言（原料符合日本PL制度的声明/证明） — フタPP・パッキン | PL制度適合確認 | 強く推奨 |
| 5 | 塗装仕様書（涂装规格: 粉体塗装の塗料種別・飲食接触面への回り込み有無） | 塗装面の食品接触判定（3.2） | 強く推奨 |
| 6 | 工場の品質認証（ISO9001等）・他社ブランドの製造可否確認 | 参考情報（法規ではなく体制評価） | 任意 |

- これら書類の**有無自体を工場見積（Quote）比較の評価軸に含める**（書類が出せない工場は法規リスク・LT増）。
- 受領書類は Document として原本保存し、AIが要点構造化 → REGがレビュー（構造化時点でSoT、Governance §11準拠）。

## 4. Hard Gate 連動設計（G-03運用詳細）

### 4.1 原則

- **G-03（HARD）: Regulatory=BLOCKED → 該当工程停止。Override不可**（解除はREGによるStatus変更のみ）。Governance Pack §9 に完全準拠。
- **Soft運用の範囲**: 法規未確認（NOT_CHECKED/CHECKING/REVIEW_REQUIRED）でも **RFQ・サンプルは警告付きで進行可**とする。理由: 法規確認には試験サンプルが必要であり、サンプル前に法規確定を求めると工程がデッドロックするため。
- **Hardの範囲**: PRODUCTION_READY / SHIPMENT_READY は法規確定（APPROVED または NOT_APPLICABLE）なしに true にならない（§7 Governance変更提案-2 参照）。

### 4.2 Regulatory Status × Readiness 対応表

| Regulatory Status | RFQ_READY | SAMPLE_READY | PRODUCTION_READY | SHIPMENT_READY |
|---|---|---|---|---|
| NOT_CHECKED | ○（WARN: 法規未チェック） | ○（WARN） | **✕（不足理由: 法規未確認）** | **✕** |
| CHECKING | ○（WARN） | ○（WARN） | **✕** | **✕** |
| REVIEW_REQUIRED | ○（WARN: REGレビュー待ち） | ○（WARN。ただし試験計画の起票を必須Taskとして自動生成） | **✕** | **✕** |
| APPROVED | ○ | ○ | ○（他条件が満たされれば） | ○（同左） |
| NOT_APPLICABLE | ○ | ○ | ○ | ○ |
| **BLOCKED** | ○*（WARN: BLOCK理由の表示付き） | **✕（G-03）**※是正のための試験用サンプルは例外Task経由で可 | **✕（G-03）** | **✕（G-03）** |

- \* BLOCKED時のRFQ: 新工場・代替仕様の探索は是正手段になり得るため停止しない（WARN+理由表示）。ただし**BLOCK原因が商品仕様そのものの違法性である場合はREG判断で案件をON_HOLD推奨**。
- ✕ の場合、Readinessの不足理由リストに「Regulatory: {Status}（{未完了事項}）」を必ず出力する（Governance §3のReadiness定義に準拠）。
- ProductRisk = `PRISK_CRITICAL` の案件は、SAMPLE_READY も法規確定前は WARNではなく承認必須（`WAITING_APPROVAL`）に格上げする（01の§3「Critical→法規Hard Gate強化」の具体化。Gate新設ではなくTask承認要件で実現）。

### 4.3 Gate Engine 実装要件（B1への引継ぎ）

- G-03判定は Regulatory Status の参照のみで完結させる（判定ロジックをGate側に複製しない）。
- BLOCKED設定・解除は必ずApproval記録+AuditLogを伴う。DB制約+アプリ層の二重防御（Governance §9）。
- Status が APPROVED 後に関連SpecFieldが変更された場合、自動で CHECKING に差し戻り、PRODUCTION_READY が false に戻ることをState Machineで保証する（A3連携）。

## 5. Early Warning 設計（Proposal段階の顧客予告）

### 5.1 仕組み

- Requirement Analyzer の解析時点で、Input Profile から**重大法規トリガ**（食品接触 / 電気 / 無線 / 子供用品 / 肌接触・化粧品領域 / 抗菌等の訴求）を検知したら、Proposal（OPTION A/B/C）に**法規予告ブロック**を自動挿入する（`A_FULL_AUTO`、文言はA2承認済みテンプレートのみ使用）。
- 目的: (1) 後工程での「聞いてない」コスト・LT増の防止、(2) 商社の専門性の訴求（安心感）、(3) 顧客の予算・納期期待値の早期調整。
- 文言原則（A2のJust-in-Time Education文言と整合）: 専門用語を使わない / 不安を煽らず「当社が代行する」姿勢 / 費用・期間は幅で示す / 断定しない。

### 5.2 表現例（A2文言集への提供。3件+汎用1件）

1. **食品接触（タンブラー等）**:
   「飲み物や食べ物に直接ふれる商品は、日本で販売する前に安全性の確認（材質の検査など）が法律で求められています。検査の手配や輸入時の手続きは当社がすべて代行しますので、ご安心ください。目安として、検査に3〜6週間・10〜30万円程度の費用がかかる場合があります。スケジュールとお見積りに含めてご提案します。」
2. **電気製品**:
   「コンセントや充電を使う商品は、日本の安全基準（PSEマークなど）への適合確認が必要になることがあります。対応済みの工場選びから認証の確認まで当社がサポートします。認証の状況によっては、準備期間が数週間〜数か月変わることがあるため、早めに一緒に確認させてください。」
3. **子供用品・玩具**:
   「お子さま向けの商品は、大人向けよりも安全性の確認項目が多くなります（材質・小さな部品・塗料など）。日本で安心して販売いただけるよう、必要な検査と表示を当社で整理してご案内します。対象年齢を教えていただくと、必要な確認をより正確にお伝えできます。」
4. **汎用（無線・訴求表現等の検知時）**:
   「この商品には、日本で販売する際に確認が必要なルールがある可能性があります（例: 通信機能の認証、性能表示の根拠など）。次のご提案までに当社で確認ポイントを整理し、費用や期間への影響と合わせてお知らせします。」

- いずれの文言も末尾に固定注記: 「※法令に関する最終的なご案内は、確認完了後に改めてお伝えします。」

## 6. 免責・体制（責任分界）

### 6.1 システム表示文言（全Regulatory出力・帳票・Portal画面に固定表示）

> 「本チェック結果はAIによる参考情報（適用法規の**候補**）であり、法令適合の最終判断ではありません。最終的な法令適合の判断は、当社法規担当による確認、および必要に応じて有資格の専門家（行政書士・弁理士等）・登録検査機関・所轄機関（検疫所・消費者庁・経済産業省・総務省等）への確認を要します。法令・通知は改正されるため、実務では常に最新の情報を確認してください。」

- 顧客向け画面では平易版を表示: 「この情報は現時点の参考情報です。正式なご案内は、当社担当者による確認の完了後にお伝えします。」
- 工場向け（中国語）帳票にも同趣旨を記載（A5の文書テンプレートに組込み依頼）。

### 6.2 責任分界

| 主体 | 責任範囲 | やらないこと |
|---|---|---|
| AI（Regulatory Engine） | 候補生成・照合・変更検知・書類の構造化・進捗督促 | 最終判断 / NOT_APPLICABLE・BLOCKED解除の確定 / 顧客・工場への確定的回答 |
| REG（法規担当） | 候補の採否確定・Status確定・試験/表示計画の承認・外部専門家の起用判断・検疫所等への照会 | 弁理士・行政書士の独占業務に属する対外手続の代理 |
| MGR | NOT_APPLICABLE の二重承認・REG代理承認・BLOCKED時の事業判断（案件中止/仕様変更） | — |
| 外部専門家（行政書士・弁理士・登録検査機関等） | 専門的見解の提供・試験の実施・出願/手続の代理 | 商社の事業判断 |
| 顧客（CLIENT） | 自社ブランド表記・販売方法（訴求文言の最終採用）の決定 | — |

- 契約実務への引継ぎ（Phase 0外・メモ）: 顧客との取引条件書に法規対応の役割分担（費用負担・訴求文言の責任）を明記することを推奨。

## 7. Governance変更提案（2件）

Governance Pack §9 の手続に従い、以下を統合レビュー（14番）に起案する。**採否確定まで本書はWARN表示等の既存枠組み内で運用可能な記述としている。**

### 提案-1: Soft Gate `G-14 Regulatory未確認` の新設

| 項目 | 値 |
|---|---|
| gate_id | G-14 |
| name | Regulatory未確認 |
| type | SOFT |
| checkpoint | RFQ発行時・サンプル発注時 |
| condition | Regulatory Status ∈ {NOT_CHECKED, CHECKING, REVIEW_REQUIRED} |
| blocked_actions | なし（WARN表示+法規確認Taskの自動起票のみ） |
| evidence | Regulatory Assessment（checklist版数付き） |
| override | WARN付き進行可 |
| 理由 | 「法規未確認のままRFQ・サンプルが進んでいる」ことを可視化し、PRODUCTION_READY直前での手戻りを防ぐ。G-10〜G-13と同格のSoft Gateとして登録したい |

### 提案-2: G-03 の条件補記（Readiness必須条件の明文化）

- 現行 G-03 は `Regulatory=BLOCKED → Production/Shipment停止` のみを定義している。これに加え、**Readiness定義の注記として「PRODUCTION_READY / SHIPMENT_READY は Regulatory Status が APPROVED または NOT_APPLICABLE であることを必須条件とする（BLOCKED以外の未確認Statusでも true にならない）」**を Governance Pack §3（Readiness行）または §9（G-03行）へ追記することを提案する。
- 理由: 「BLOCKEDでなければ量産可」と誤読されると、未確認のまま量産に入る抜け道が生じる（=本書§1.1の「見落とし」と同型の最悪失敗）。本書§4.2はこの解釈を前提に書かれており、Governance本文への明文化で二重防御としたい。
