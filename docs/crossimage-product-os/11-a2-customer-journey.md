## 1. Customer Journey 全体設計

### 1.1 3層構造と顧客心理5段階の対応

顧客に見せる旅は3層構造とする。顧客への表示名は「アイデアをかたちに」「プランを固める」「実現の最終確認」のみであり、**DREAM / PLAN / REALITY CHECK は内部レイヤーコード（顧客には表示しない）**である（19番 §14「日本語主・英語従」準拠）。内部では顧客心理Status（`IDEA / EXCITED / CONVINCED / COMMITTED / ORDERED`、**顧客には絶対に非表示**）で管理する。

| 層 | 顧客に見せる名称（UI表示） | 顧客がすること | 内部の顧客心理Status | 主な内部処理 |
|---|---|---|---|---|
| DREAM | 「アイデアをかたちに」 | 自由文・画像・URLで想いを話す | `IDEA` → `EXCITED` | Requirement Analyzer実行、ProjectDNA推定（`AI_SUGGESTED`）、Proposal Engine起動 |
| PLAN | 「プランを固める」 | OPTION A/B/C から選ぶ、最小限の質問に答える | `EXCITED` → `CONVINCED` | Proposal確定（G-10）、SpecField積み上げ、Quality選択→内部Tier変換 |
| REALITY CHECK | 「実現の最終確認」 | 数量・予算・納期・重点管理項目を確認して確定 | `CONVINCED` → `COMMITTED` → `ORDERED` | Requirement確定、RFQ_READY判定、RFQ発行（G-13）、以降 見積→サンプル→PO |

- 心理Statusは Progress Report Engine・Next Best Action Engine の入力にのみ使用。顧客UIには一切露出しない（「あなたは今EXCITEDです」等は禁止）。
- 心理Statusの推定材料: 入力の具体性、返信速度、数量・納期の言及有無、価格質問の頻度。推定は `AI_SUGGESTED` 扱いで、SALESが上書き可（AuditLogに記録）。

### 1.2 固定一本道にしない（Skip / Fast Track / 途中参加）

Journeyは表示上の地図であり、**Workflowは Task Generator が ProjectDNA + Entry Route から動的生成**する。以下を明示的に許可する。

| パターン | 条件（DNAキー） | 挙動 |
|---|---|---|
| DREAM層スキップ | `EXP_INTERMEDIATE` 以上 かつ 商品仕様の言及あり | Entry Route B から PLAN層直入。Proposal Engineは補助提案のみ |
| Fast Track | `EXP_PROFESSIONAL` かつ CAD/BOM/仕様書アップロードあり | DREAM・PLAN層を経由せず REALITY CHECK（RFQ準備）へ直行。初心者向け質問・教育文言を全て抑止 |
| 途中参加 | 他社で頓挫した案件（既存見積・サンプル持ち込み） | 持込資料をRequirement Analyzerが解析し、確定済み項目を `PROVISIONAL` で取り込み。既回答の質問は再質問しない |
| 逆戻り | REALITY CHECKで予算不成立 | PLAN層のOPTION再提示（数量・品質を変えた再計算）。「最初からやり直し」にしない |
| Repeat | Entry Route D | Journey表示自体を省略し、差分確認画面のみ |

- 層をまたぐ移動でも入力済みデータは全て保持（SpecFieldのStatusで管理し、二重入力を禁止する）。
- Soft Gate（G-10〜G-15）は WARN 付き進行可のため、Journey上「未確定のまま先へ進む」導線を常に残す。Hard Gate（G-01〜G-06）該当工程のみ進行ボタンを物理的に無効化する。

## 2. 4 Entry Route の画面フロー

入口選択画面は設けない。トップの入力欄に自由文を書けば自動で Route A、商品名+数量が揃っていれば Route B、ファイル添付があれば Route C、既存顧客のログイン後「前回の商品」カードから Route D。**顧客にRoute名は見せない**（内部管理用）。

### 2.1 Route A: IDEA MODE（相談ベース）

| # | 画面 | 顧客の入力 | 備考 |
|---|---|---|---|
| A-1 | 「どんな商品を作りたいですか？」 | 自由文（必須）+ 画像/URL（任意） | **これだけで開始可能**。他の必須項目なし |
| A-2 | AI質問（BLOCKERのみ、最大3問） | 選択式中心 | 質問0件ならスキップ |
| A-3 | ご提案A/B/C（OPTION A/B/C）提案 | 1案選択 or「相談したい」 | 概算単価・MOQ・納期・Trade-off入り。顧客画面の初出は「ご提案A/B/C（OPTION A/B/C）」表記 |
| A-4 | プラン確認（IMPORTANT_LATER質問を段階表示） | 数量・品質レベル等 | 未回答でも保存可 |
| A-5 | 実現確認（Requirement確定） | 確定ボタン | 確定後「見積依頼（RFQ）の準備に進みます」表示（§8 STEP 11の「見積依頼を送ります」と文言統一） |

初回入力→提案まで顧客操作 **3ステップ以内**（A-1入力 → A-2回答 → A-3閲覧）。

### 2.2 Route B: PRODUCT MODE（商品確定済）

| # | 画面 | 顧客の入力 |
|---|---|---|
| B-1 | 商品情報入力 | 商品名/カテゴリ、参考画像/URL、数量、目標単価（任意）、希望納期（任意） |
| B-2 | カスタマイズ範囲 | ロゴのみ/色・パッケージ/形状から作る（内部で OdmLevel へ変換） |
| B-3 | AI質問（BLOCKERのみ） | 選択式 |
| B-4 | プラン確認→Requirement確定 | 確定ボタン |

**4ステップ**。Proposal Engineは「比較用の代替案」として控えめに1枠だけ表示（押し付けない）。

### 2.3 Route C: FAST TRACK（CAD/BOM/仕様書保有）

| # | 画面 | 顧客の入力 |
|---|---|---|
| C-1 | ファイルアップロード | CAD/BOM/仕様書/図面（複数可）+ 数量・希望納期 |
| C-2 | 解析結果確認 | AIが抽出した仕様一覧を確認・修正（Known項目は再入力させない） |
| C-3 | RFQ準備確認 | 「見積依頼へ進む」ボタン |

**3ステップ**。初心者向け質問・教育文言は全て抑止（§9）。

### 2.4 Route D: REPEAT ORDER

| # | 画面 | 顧客の入力 |
|---|---|---|
| D-1 | 前回商品カード選択 | 「同じものを再注文」タップ |
| D-2 | 差分確認 | 数量・納期のみ入力。仕様変更有無を Yes/No（Yes ならECRフローへ） |
| D-3 | 確定 | 確定ボタン → 即 RFQ_READY 判定 |

**3ステップ・仕様再入力ゼロ**。前回Specificationをコピーし全Field `CONFIRMED` を維持、変更点のみ再確認。

## 3. Minimum Question 設計

### 3.1 パイプライン

```
顧客入力（自由文/画像/URL/ファイル）
  → Requirement Analyzer が5分類
     Known（判明）/ Missing（不足）/ Conflicting（矛盾）/
     Assumption（AI補完可能な仮定）/ Critical Missing（これが無いと提案不能）
  → 質問候補を生成し3分類（QuestionClass正準enum、Governance Pack v1.1 §3）
     BLOCKER          : Critical Missing 由来。Proposal確定を止める（G-10、Soft）
     IMPORTANT_LATER  : Missing/Conflicting 由来。RFQ〜サンプルまでに必要
     OPTIONAL         : Assumptionの確認。答えなくても既定値で進行
  → SpecFieldへの反映
     Known→PROVISIONAL / Assumption→AI_SUGGESTED / Missing・Critical Missing→UNKNOWN
     顧客が回答→PROVISIONAL、Requirement確定操作→CONFIRMED
```

> ※ 質問候補は Requirement Analyzer の動的質問（Known/Missing分類由来）に加え、**Category Rule Pack + 属性タグ由来の定型必須質問（Rule Engine の QuestionList）から供給される**（18番 §8.2 接続仕様。重複は target_spec_field キーで排除）。質問・CTQをカテゴリー固有ロジックとしてハードコードしない（Governance §13）。

### 3.2 運用ルール

1. **質問総量の上限はDNA連動**: `EXP_BEGINNER`=BLOCKERのみ即時、他は工程到達時に小出し。`EXP_PROFESSIONAL`=BLOCKER以外は一覧で一括提示（小出しの方が失礼）。
2. **Conflicting は質問ではなく「確認」として提示**（例:「画像は450mlに見えますが、文章では350mlとありました。どちらにしますか？」）。顧客を責める文言禁止。
3. **Assumption は勝手に確定しない**: 画面に「当社の想定: ステンレス真空断熱（変更できます）」のように必ず可視化し、`AI_SUGGESTED` のまま保持。
4. 同じ質問を二度しない（回答済みはSpecFieldに残り、全Route・全工程で共有）。
5. BLOCKER未回答でもG-10はSoftのため、「あとで答える」を常に選べる。ただしProposal確定ボタンにWARN表示。

### 3.3 質問UI原則

- **一度に最大3問**。4問以上必要でも3問ずつ段階表示。
- **BLOCKERのみ即時**。IMPORTANT_LATERはその情報が必要になる工程の直前に表示（Just-in-Time）。
- **専門用語禁止**（AQL/CTQ/ODM/Pantone等）。色は「色見本の写真アップ or 近い色を選択」で受け、内部でPantone候補化（G-11対応）。
- 全質問に「わからない → おすすめで進める」選択肢を必ず付ける（選択時 `AI_SUGGESTED` で進行）。
- 各質問に**理由を一行添える**（「→ 数量で1個あたりの価格が大きく変わるため」）。
- 選択式＞数値入力＞自由文の優先順で設計。スマホ片手操作で回答可能にする。

## 4. Just-in-Time Education（ちょうどいいタイミングの豆知識）

### 4.1 表示ルール（テンプレート + AI生成のハイブリッド）

| ルール | 内容 |
|---|---|
| タイミング | 関連する入力欄・質問・選択肢が**画面に現れた瞬間**にのみ表示。事前学習ページは作らない |
| 形式 | 入力欄直下の1〜2行カード（💡アイコン）。タップで3〜4行の詳細展開 |
| 生成方式 | カテゴリ×工程のテンプレート文言集（本書が正）をベースに、AIが顧客の入力文脈（用途・数量・チャネル）で語尾・数値を差し込み。**テンプレートに無い教育文言のAI新規生成はSALES承認後に文言集へ追記**（B_AI_DRAFT） |
| 表示条件 | `EXP_BEGINNER`=全表示 / `EXP_INTERMEDIATE`=詳細折りたたみ / `EXP_PROFESSIONAL`=非表示 |
| トーン | 「知らないと損する豆知識」。教科書調・上から目線・不安煽り禁止。安全・法規のみ明確なEarly Warning（§4.3） |
| 量 | 1画面に同時表示は最大2件。既読カードは自動的に畳む |

### 4.2 タンブラーでの具体文言例（テンプレート10件）

> ※ テストケース第1号（タンブラー）の例であり、システム仕様ではない（Governance §0-2/§13）。文言テンプレートはカテゴリー別のデータとして管理し、コードにハードコードしない。

| # | 表示タイミング | 文言（顧客表示そのまま） |
|---|---|---|
| E-01 | 用途の質問表示時 | 💡 バッグに横向きで入れて持ち歩くなら「密閉性能」が重要です。フタの構造で漏れにくさが大きく変わります。 |
| E-02 | 数量入力欄表示時 | 💡 数量で1個あたりの価格が大きく変わります。また、形から作る場合は数量によって金型の条件（負担方法）も変わります。 |
| E-03 | 保温・保冷の選択時 | 💡 「二重構造（真空断熱）」なら保温・保冷ができ、結露もしにくくなります。単層より価格は上がりますが、ドリンク用途では定番です。 |
| E-04 | 容量の選択時 | 💡 350mlはコンビニコーヒーMサイズ相当、450mlはタンブラーの売れ筋サイズです。車のドリンクホルダーに入れるなら底の直径もチェックポイントです。 |
| E-05 | ロゴ・印刷の選択時 | 💡 印刷方法で仕上がりと価格が変わります。1色ロゴは低コスト、写真のようなフルカラーやレーザー彫刻は高級感が出ますが単価が上がります。 |
| E-06 | 色選択時 | 💡 画面の色と実物の色は必ず少しズレます。ブランドカラーがある場合は、色見本や既存グッズの写真をアップいただくと量産時の色ブレを防げます。 |
| E-07 | 品質レベル選択時 | 💡 販売価格帯に合った品質レベルがおすすめです。ノベルティ配布なら「コスト重視」、自社ブランドで販売するなら「ブランド重視」を選ぶ方が結果的にクレーム対応コストを抑えられます。 |
| E-08 | 納期の質問表示時 | 💡 海外生産は「作る時間+船で運ぶ時間」がかかります。既製品ベースなら約1〜1.5ヶ月、形から作る場合は3ヶ月前後が目安です。販売開始日から逆算しましょう。 |
| E-09 | パッケージ選択時 | 💡 ギフト・EC販売なら箱の印象が購入体験を左右します。無地箱→オリジナル箱への変更は1個あたり数十円の追加で可能なことが多いです。輸送中の傷防止にも役立ちます。 |
| E-10 | サンプル案内表示時 | 💡 量産前に必ず実物サンプルで確認します。写真ではわからない「手に持った重さ・フタの開けやすさ・色味」をここでチェックするのが失敗しないコツです。 |

### 4.3 Early Warning（安全・法規のみ、明確に表示）

- 表示例（タンブラー、飲料が触れる容器のため食品衛生法の対象）:
  > ⚠️ **お知らせ（重要）**: 飲み物に直接触れる商品は、法律で定められた検査（食品衛生法）に合格する必要があります。検査の手配は当社が行いますが、費用（目安10〜30万円）と3〜6週間程度の期間がかかります。スケジュールに織り込んでご案内します。（費用・期間はA6 §3.2の試験リスト目安と整合）
- 「量産成功のための重点管理項目」のポジティブ表現とは区別し、Early Warningは黄色帯+⚠️で早期（Proposal画面）に表示。Regulatory Statusが `BLOCKED` の場合の工程停止（G-03）は社内側で管理し、顧客には「必要な検査の完了をお待ちください」と表示する。

## 5. YOUR DECISION / OUR RECOMMENDATION / FACTORY RESPONSE の3分離表示

顧客が「誰の発言か」を誤解しないよう、意思決定に関わる全画面で情報源を3色に分離する。

| 区分 | UI表示名 | 色/形式 | 内容 | 編集権 |
|---|---|---|---|---|
| YOUR DECISION | 「あなたの決定」 | 青枠・鍵アイコン | 顧客が確定した事項（SpecField `CONFIRMED` のうち顧客決定分） | 顧客（変更は変更手続き経由） |
| OUR RECOMMENDATION | 「当社のおすすめ」 | 緑枠・💡 | AI+SALESの推奨値・代替案・理由（`AI_SUGGESTED` / `PROVISIONAL`） | 商社 |
| FACTORY RESPONSE | 「工場からの回答」 | グレー枠・🏭 | 工場実現可否・MOQ・納期等の事実回答（**価格は必ずQuotation化した顧客見積のみ表示。Quote＝工場見積の生数値は絶対に出さない**） | 表示のみ |

※ 区分名（YOUR DECISION / OUR RECOMMENDATION / FACTORY RESPONSE）は内部設計上の区分キーであり、画面上は「あなたの決定」「当社のおすすめ」「工場からの回答」の日本語UI表示名のみを表示する（英語区分名を顧客画面に出さない。19番 §5 #4）。

画面設計原則:
1. 1画面内で3区分が混在する場合も必ず枠色で分離。「おすすめ」を既定選択にしても、確定操作なしに「あなたの決定」へ昇格させない。
2. FACTORY RESPONSE は翻訳済みの要約のみ。工場名・原価・他工場比較は表示しない（情報遮断、Governance §8）。
3. 「あなたの決定」には決定日時を表示し、後日の「言った/言わない」を防ぐ（AuditLog連動）。
4. 推奨と決定が食い違う場合（例: 顧客がコスト重視を選んだが販売価格帯はブランド重視相当）は、緑枠内に理由付きで再提案を残すが、進行は止めない。
