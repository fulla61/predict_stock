## 分類の定義

- **A：Phase 0 で絶対決定が必要** — 後から変えると全面改修・事故・信頼毀損につながる「基礎」
- **B：暫定決定して MVP（実用最小限の製品：最初に作る最小構成）検証後に変更可能** — データ・テンプレート駆動で変更コストが低いもの
- **C：現時点では決めない方がよい** — 実測なしに決めると誤る運用パラメータ。本セットでは**項目単位のCはなし**、各項目内の「今決めない要素」として §12 に列挙

## ④ Project DNA（05番§4）— 分類 A

| 観点 | 内容 |
|---|---|
| 決定事項 | 案件を特徴づける8軸（顧客経験/発注意欲/ODMレベル（改造の深さ）/商品リスク/品質レベル/ブランド影響/工場リスク/商事リスク・優先度）とその値の確定 |
| なぜオーナー判断か | 全システムの分岐キー。質問数・工程・承認段数・検品密度・報告頻度がすべてこの軸を参照する。**後から軸を変える＝全面改修** |
| 推奨案 | 8軸構成と正準コードを確定承認。値の追加は可、軸の削除・意味変更は不可とする |
| 代替案 | (a)軸を減らして簡素化（例: 5軸） (b)軸を増やす |
| 推奨理由 | 8軸は御社の「属性×目的×水準で案件ごとに設計を変える」思想の最小表現。減らすと品質と営業の両立が崩れ、増やすと初期運用が回らない |
| メリット | 案件ごとの最適化が仕組み化され、属人判断が減る |
| デメリット/リスク | 軸が多く初期は使いこなせない可能性 → AI推定+人間確定で緩和済み |
| コスト・工数影響 | 確定なら追加コストなし。後日変更は高コスト |
| 顧客UXへの影響 | 経験レベル軸が質問量・説明量を決める（初心者に優しく、プロに速く） |
| 日本側業務への影響 | Task生成・承認段数の自動決定の基盤 |
| 中国側業務への影響 | 工場リスク軸が検品密度・監査要否を決める |
| 品質・法規への影響 | 品質レベル軸・商品リスク軸が品質Tier推薦・法規チェック強度に直結 |
| 将来変更の難易度 | **高**（軸変更は全面改修）。値追加は低 |
| 推奨する承認内容 | **「8軸+正準コードを確定承認。派生ロジックの閾値（質問数・検品密度等）は暫定としMVPで調整可」** |

## ⑥ Gate定義（05番§9、G-01〜G-16）— 分類 A

| 観点 | 内容 |
|---|---|
| 決定事項 | Hard Gate（絶対に突破できない関門）6本: 正式発注なし/ゴールデンサンプル未確定/法規BLOCKED/重大問題未解決/検品未完了/無断変更検知 ＋ Soft Gate（警告付きで進める関門）7本（G-10〜G-16） |
| なぜオーナー判断か | 「入口は柔軟、出口は厳格」という安全哲学の実体。事故・法令違反・無断量産を防ぐ最後の防衛線を緩めるか締めるかは経営責任そのもの |
| 推奨案 | Hard 6本とHard/Soft区分を確定承認。Soft 7本は暫定（WARN頻度を運用で見て調整） |
| 代替案 | (a)Hardを増やす（例: 法規未確認でRFQも停止）→安全側だが受注率低下 (b)Hardを減らす→速いが事故リスク |
| 推奨理由 | 現行6本は「安全・法令・契約・品質証跡」の最小限で、営業速度を落とさず致命傷だけ防ぐ均衡点 |
| メリット | 「言った言わない」「勝手に量産」「検品なし出荷」が構造的に不可能になる |
| デメリット/リスク | 緊急出荷等でGateが邪魔に感じる場面が出る → それでも突破不可が正しい（承認記録を残して状態を変えるのが唯一の道） |
| コスト・工数影響 | 中（DB制約+アプリ層の二重防御実装） |
| 顧客UXへの影響 | 顧客には「量産成功のための管理ポイント」としてポジティブに表示 |
| 日本側業務への影響 | 承認業務がGateに集約され、確認作業が減る |
| 中国側業務への影響 | 無断変更検知（G-06）が工場統制の根拠になる |
| 品質・法規への影響 | 最大。安全・法令がTier（品質等級）で緩和されない仕組みの根幹 |
| 将来変更の難易度 | Hard追加は容易。削除は運用が依存するため危険 |
| 推奨する承認内容 | **「Hard 6本+区分を確定承認。Soft 7本は暫定承認とし、追加・調整はGovernance変更手続による」** |

|---|---|

| デメリット/リスク | 等級判定を誤ると期待外れ → AI推薦+人間承認（C_HUMAN_DECISION）で緩和 |
| コスト・工数影響 | 中。パラメータ駆動なので数値調整は低コスト |
| 顧客UXへの影響 | 専門用語なしの4択で品質を選べる |
| 日本側業務への影響 | 品質設計の標準化により属人性が減る |
| 中国側業務への影響 | 検品密度・限度見本運用が等級から自動決定 |
| 品質・法規への影響 | FIXED MINIMUMが法令・安全の絶対下限を保証 |
| 将来変更の難易度 | 構造変更は高（DNA・Rule Engineと結合）。数値調整は低 |
| 推奨する承認内容 | **「4段階+FIXED MINIMUMを確定承認。26パラメータ数値は暫定としMVP・実案件で校正」** |

## ⑨ 権限設計（05番§8+15番RBAC）— 分類 A

| 観点 | 内容 |
|---|---|
| 決定事項 | Role（役割）11種と情報遮断マトリクス: 顧客には工場原価・商社粗利・他工場情報を見せない / 工場には顧客販売価格・粗利・他工場情報を見せない。画面だけでなくExcel出力・WeChat要約にも適用。Hard Gate承認者の代理ルール |
| なぜオーナー判断か | 情報漏洩は一発で信頼と粗利構造を失う。「何を誰に見せないか」は商売の守秘構造であり経営そのもの |
| 推奨案 | 遮断マトリクスと代理承認ルールを確定承認 |
| 代替案 | (a)遮断を画面のみに限定（帳票は運用注意で対応） (b)さらに細かい項目単位権限 |
| 推奨理由 | 漏洩事故の最頻経路は帳票・添付ファイル。全チャネル遮断を最初から仕組みにしないと必ず事故る。項目単位の細分化は初期には過剰 |
| メリット | 誤送信・見せてはいけない数字の混入が構造的に防止される |
| デメリット/リスク | 権限設定の初期手間 |
| コスト・工数影響 | 中（出力系への遮断適用と自動テスト） |
| 顧客UXへの影響 | なし（見えないものが正しく見えないだけ） |

## ⑩ Automation Matrix（10番文書）— 分類 B

| 観点 | 内容 |
